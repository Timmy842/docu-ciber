# Hack The Box — Starting Point 1: Fawn

Notas sobre **FTP** (puerto 21), enumeración con **Nmap**, cliente `ftp` y acceso **anónimo**. La flag se obtiene descargando un archivo del servidor; **no publiques la flag** en sitios abiertos.

---

## Contexto

**Fawn** introduce el protocolo **FTP** (*File Transfer Protocol*): transferencia de archivos cliente-servidor. El FTP clásico **no cifra** tráfico (credenciales y datos van en claro), por eso existen alternativas modernas.

---

## Conceptos del módulo (respuestas a las tareas)

### Tarea 1 — ¿Qué es FTP?

**FTP** = **File Transfer Protocol** (*protocolo de transferencia de archivos*).

### Tarea 2 — Puerto habitual de FTP

**21/tcp** es el puerto de **control** del FTP. El canal de datos puede usar otros puertos según modo (activo/pasivo).

### Tarea 3 — Protocolo similar a FTP pero seguro, extensión de SSH

**SFTP** (*SSH File Transfer Protocol*). No confundir con **FTPS** (FTP sobre TLS/SSL): ambos mejoran la seguridad, pero **SFTP** va sobre **SSH** y es distinto del FTP tradicional.

### Tarea 4 — Comando para ICMP echo request

**ping** (igual que en Meow). Ejemplo:

```bash
ping -c 2 TARGET_IP
```

### Tarea 5 — Versión de FTP en el objetivo (según escaneo)

En el laboratorio estándar suele reportarse **vsftpd 3.0.3** (*Very Secure FTP Daemon*, popular en Linux).

### Tarea 6 — Tipo de SO (según escaneo)

**Unix** (Nmap infiere familia Unix/Linux por huellas del stack y del servicio).

### Tarea 7 — Ayuda del cliente FTP en línea de comandos

**`ftp -?`** muestra la ayuda en muchos sistemas (en algunos también `ftp --help` o `man ftp`).

```bash
ftp -?
```

### Tarea 8 — Usuario para “sin cuenta” en FTP

**anonymous**. Convención histórica: acceso público de solo lectura (o subida restringida) con email como “contraseña” a menudo aceptada como texto cualquiera.

### Tarea 9 — Código de respuesta “Login successful”

**230** — en el protocolo FTP, **230** significa que el usuario ha iniciado sesión correctamente (mensaje típico: *User logged in*).

### Tarea 10 — Listar archivos (además de `dir`)

**ls**. En el cliente `ftp`, tanto `dir` como `ls` suelen listar el directorio remoto (detalle depende del cliente/servidor).

### Tarea 11 — Descargar un archivo del servidor FTP

**get** (descarga un archivo del servidor al cliente). Para subir sería **put**.

## Metodología: reconocimiento

### 1. Conectividad

```bash
ping -c 4 TARGET_IP
```

### 2. Nmap enfocado a FTP

**Escaneo general:**

```bash
nmap -sC -sV TARGET_IP
```

- Verás **21/tcp** abierto con **ftp** y la versión (**vsftpd 3.0.3** en el writeup estándar).

**Solo FTP:**

```bash
nmap -p 21 -sV TARGET_IP
```

**Scripts FTP útiles (opcional):**

```bash
nmap -p 21 --script ftp-anon,ftp-syst TARGET_IP
```

- `ftp-anon`: comprueba si el FTP anónimo está permitido.
- `ftp-syst`: a veces obtiene información del sistema vía comando `SYST`.

## Metodología: cliente `ftp`

### Iniciar sesión anónima (modo interactivo)

```bash
ftp TARGET_IP
```

Secuencia típica:

1. `Name`: escribe `anonymous`
2. `Password`: a menudo puedes poner algo como `anonymous@` o dejar un correo ficticio; depende del servidor

**Modo no interactivo (una línea, útil en scripts):**

```bash
ftp -inv TARGET_IP <<EOF
user anonymous anonymous@
ls
bye
EOF
```

- `-i`: desactiva modo interactivo en algunos clientes.
- `-n`: no autologin; luego `user` envía usuario y contraseña.

*(La sintaxis exacta puede variar; en Windows el cliente puede ser distinto — en Kali/Parrot/Linux es la clásica.)*

### Comandos dentro del shell `ftp`

| Comando | Función |
|--------|---------|
| `ls` o `dir` | Listar archivos en el servidor remoto |
| `cd carpeta` | Cambiar directorio remoto |
| `lcd ruta` | Cambiar directorio **local** (donde guardas descargas) |
| `get archivo` | Descargar `archivo` al directorio local actual |
| `mget archivos` | Descargar varios (suele pedir confirmación) |
| `binary` / `ascii` | Modo de transferencia (binario vs texto) |
| `bye` o `quit` | Salir |

**Ejemplo mínimo:**

```ftp
ls
get nombre_del_archivo_flag.txt
bye
```

Luego en tu máquina:

```bash
cat nombre_del_archivo_flag.txt
```

## Qué observar en el tráfico (conceptual)

FTP manda credenciales y archivos **sin cifrar** (salvo FTPS). En una red no confiable, un atacante con sniffing podría capturar usuario/contraseña. Por eso en producción se prefiere **SFTP/SCP** o **FTPS** y restricciones de firewall.

## Resumen de comandos

| Comando | Uso |
|--------|-----|
| `nmap -sV -p 21 TARGET_IP` | Versionado del servicio FTP |
| `ftp TARGET_IP` | Cliente interactivo |
| `ftp -?` | Ayuda del cliente |
| `anonymous` + password trivial | Login de invitado |
| `ls` / `dir` | Enumerar remoto |
| `get` | Descargar la flag |

## Errores frecuentes

- **Modo pasivo vs activo**: si hay timeouts tras `ls`, a veces ayuda `passive` en el cliente `ftp`.
- **Firewall local**: asegúrate de que la VPN de HTB está activa.
- **Escribir `get` con typo**: el nombre del archivo debe coincidir exactamente (sensible a mayúsculas en muchos Unix).
