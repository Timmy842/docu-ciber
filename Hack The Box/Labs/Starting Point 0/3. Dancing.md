# Hack The Box — Starting Point 1: Dancing

Notas sobre **SMB/CIFS** en Windows, puerto **445**, herramienta **`smbclient`** de Samba, enumeración de **recursos compartidos** y descarga de archivos con **`get`**. Ideal para cerrar el trío inicial del *Starting Point* junto a Telnet y FTP.

---

## Contexto

**Dancing** expone **SMB** (*Server Message Block*), el protocolo que Windows usa para compartir archivos e impresoras en red. En Linux, el ecosistema **Samba** implementa cliente y servidor compatibles con SMB.

El flujo típico del room: descubrir **445/tcp**, listar **shares** con `smbclient`, conectar sin contraseña (o con contraseña vacía) al share permitido y descargar la flag.

---

## Conceptos del módulo (respuestas a las tareas)

### Tarea 1 — ¿Qué es SMB?

**SMB** = **Server Message Block** (*bloque de mensajes del servidor*). Microsoft lo usa como base de red para recursos compartidos; históricamente evolucionó hacia **CIFS** y versiones modernas del protocolo sobre TCP.

### Tarea 2 — Puerto en el que opera SMB (sobre TCP)

**445/tcp** es el puerto estándar **SMB directo sobre TCP** (desde Windows 2000 en adelante). El **NetBIOS** antiguo usaba otros puertos (137/138/139); en escaneos actuales **445** es el que más verás para file sharing.

### Tarea 3 — Nombre del servicio en Nmap para 445

A menudo aparece como **microsoft-ds** (nombre registrado en `nmap-services` para ese puerto).

### Tarea 4 — Flag de `smbclient` para listar shares

**`-L`** (*list*). Lista los nombres de recursos compartidos visibles desde el cliente.

```bash
smbclient -L //TARGET_IP -N
```

- `-L`: **listar** shares del servidor.
- `//TARGET_IP`: notación UNC-style en Samba (`//host`).
- `-N`: **sin contraseña** (null session / guest, según permita el servidor).

Si el servidor pide usuario:

```bash
smbclient -L //TARGET_IP -U guest
```

o contraseña vacía según el caso.

### Tarea 5 — ¿Cuántos shares hay en Dancing?

En la versión estándar del laboratorio se esperan **4** recursos listados (algunos pueden ser administrativos como `IPC$`, `ADMIN$`, etc., y uno usable para la flag).

### Tarea 6 — Share accesible con contraseña en blanco

**WorkShares** — el share “humano” donde suelen estar documentos; en el ejercicio se accede sin credenciales reales (invitado / null).

### Tarea 7 — Comando en el “SMB shell” para descargar

**`get`** — igual filosofía que en FTP: trae un archivo del recurso remoto al directorio local actual de la sesión.

## Metodología: reconocimiento

### 1. Conectividad

```bash
ping -c 4 TARGET_IP
```

### 2. Nmap a SMB

```bash
nmap -p 445 -sC -sV TARGET_IP
```

- `-p 445`: SMB.
- `-sV`: versiones (Samba, Windows build, etc.).
- `-sC`: scripts por defecto (a veces información extra).

**Scripts SMB adicionales (más ruidosos / lentos):**

```bash
nmap -p 445 --script smb-os-discovery,smb-security-mode TARGET_IP
```

- `smb-os-discovery`: intenta deducir SO.
- `smb-security-mode`: niveles de firma SMB, etc.

## Herramienta principal: `smbclient`

`smbclient` es un cliente tipo “FTP para SMB”: sesión interactiva con comandos `ls`, `cd`, `get`, `put`.

### Listar shares (`-L`)

```bash
smbclient -L //TARGET_IP -N
```

**Desglose:**

- `smbclient`: cliente Samba.
- `-L`: modo listado de shares.
- `//TARGET_IP`: objetivo.
- `-N`: no pedir contraseña (útil cuando el share permite null/guest).

Si falla `-N`, prueba usuario explícito con contraseña vacía:

```bash
smbclient -L //TARGET_IP -U ""
```

### Conectar a un share concreto

Sintaxis:

```bash
smbclient //TARGET_IP/NombreDelShare -N
```

Para **WorkShares**:

```bash
smbclient //TARGET_IP/WorkShares -N
```

Si entras correctamente verás un prompt tipo `smb: \>`.

### Comandos dentro de `smbclient`

| Comando | Descripción |
|--------|-------------|
| `help` | Lista comandos disponibles |
| `ls` | Lista archivos y carpetas en el directorio remoto actual |
| `cd carpeta` | Cambia directorio remoto |
| `lcd ruta` | Cambia directorio **local** (donde se guardan descargas) |
| `get archivo` | Descarga `archivo` al directorio local |
| `mget patron` | Varios archivos (p. ej. `mget *`) |
| `exit` | Salir |

**Flujo típico:**

```text
ls
cd SubcarpetaSiExiste
get flag.txt
exit
```

Luego:

```bash
cat flag.txt
```

*(El nombre real del archivo en tu instancia puede variar; usa `ls` para verlo.)*

## Alternativas que conviene conocer

- **`crackmapexec` / `netexec`**: enumeración y ataques a SMB en entornos reales (fuera del alcance mínimo del Starting Point).
- **Montar con `mount.cifs`** (Linux): acceso como filesystem; requiere paquete `cifs-utils`.

Ejemplo conceptual (solo si tu política y el lab lo permiten):

```bash
sudo mkdir /mnt/dancing
sudo mount -t cifs //TARGET_IP/WorkShares /mnt/dancing -o guest
ls /mnt/dancing
```

Para el room, `smbclient` suele ser suficiente.

## Seguridad: lecciones

- Shares **sin autenticación** o con **permisos mal configurados** filtran datos sensibles.
- SMB expuesto a Internet ha sido vector histórico (p. ej. **EternalBlue** era otro contexto, pero la moraleja es: parchear, restringir y usar firma SMB donde aplique).
- En pentesting autorizado, documenta siempre **qué share**, **qué credenciales** (o ausencia) y **qué archivos** demuestran el impacto.

## Resumen de comandos

| Comando | Propósito |
|--------|-----------|
| `nmap -p 445 -sV TARGET_IP` | Confirmar SMB y fingerprint |
| `smbclient -L //IP -N` | Enumerar shares |
| `smbclient //IP/WorkShares -N` | Sesión al share accesible |
| `ls`, `cd`, `get` | Navegar y descargar la flag |
