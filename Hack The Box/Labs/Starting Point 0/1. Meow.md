# Hack The Box — Starting Point 1: Meow

Notas de laboratorio y repaso de conceptos. **No incluyas la flag real en repositorios públicos**; aquí se explica el flujo y los comandos.

---

## Contexto: qué es esta máquina

**Meow** es la primera máquina del *Starting Point* de HTB. El objetivo es familiarizarte con: VPN al laboratorio, conectividad básica (`ping`), descubrimiento de servicios (`nmap`) y acceso por **Telnet** (puerto 23) con credenciales débiles o vacías.

---

## Conceptos del módulo (respuestas a las tareas)

### Tarea 1 — ¿Qué significa VM?

**VM** = **Virtual Machine** (*máquina virtual*). Es un sistema operativo completo que corre sobre un hipervisor o sobre otro SO, compartiendo hardware físico pero aislado lógicamente. En HTB, la “máquina objetivo” es una VM en la red del laboratorio.

### Tarea 2 — Herramienta para comandos por línea (consola / shell)

**Terminal** (o consola). En Linux suele ser una emulación de terminal + un *shell* (p. ej. `bash`, `zsh`). Ahí ejecutas comandos como los de OpenVPN o `nmap`.

### Tarea 3 — Servicio para la VPN a los labs de HTB

**OpenVPN**. HTB te da un archivo `.ovpn`; el cliente `openvpn` (o la app de HTB) establece un túnel cifrado hasta la red donde viven las máquinas.

**Ejemplo típico (Linux):**

```bash
sudo openvpn --config ruta/al/archivo.ovpn
```

- `sudo`: privilegios para crear la interfaz TUN/TAP y rutas.
- `openvpn`: cliente del protocolo OpenVPN.
- `--config`: archivo con endpoints, certificados y parámetros del túnel.

En Windows a menudo se usa el cliente OpenVPN GUI con el mismo `.ovpn`.

### Tarea 4 — Probar conectividad con petición ICMP echo

**ping**. Envía mensajes **ICMP Echo Request**; si el host responde con **Echo Reply**, hay ruta de red y el objetivo suele estar “vivo” (si no bloquea ICMP).

**Ejemplo:**

```bash
ping -c 4 10.10.10.16
```

- `-c 4` (Linux): envía 4 paquetes y para. En Windows sería `ping -n 4 IP`.

**Interpretación:** si no hay respuesta, puede ser firewall, host apagado, IP incorrecta o VPN mal conectada — no solo “máquina caída”.

### Tarea 5 — Herramienta común para encontrar puertos abiertos

**nmap** (*Network Mapper*). Escanea puertos TCP/UDP, detecta servicios y a veces versiones y SO.

**Escaneo básico a todos los puertos TCP más comunes (rápido):**

```bash
nmap TARGET_IP
```

**Escaneo más explícito (puertos, detección de versión, scripts por defecto):**

```bash
nmap -sC -sV TARGET_IP
```

- `-sC`: ejecuta scripts `default` de Nmap (descubrimiento útil).
- `-sV`: **detección de versión** del servicio en cada puerto abierto.

**Solo puertos concretos (rápido si ya sospechas Telnet):**

```bash
nmap -p 23 -sV TARGET_IP
```

- `-p 23`: solo el puerto 23 (Telnet).

### Tarea 6 — Servicio en el puerto 23/tcp

**Telnet**. Protocolo antiguo para acceso remoto a terminal; **no cifra** usuario, contraseña ni datos. Por eso casi nunca se usa en producción moderna, pero sigue apareciendo en CTFs y entornos legacy.

### Tarea 7 — Usuario con contraseña en blanco por Telnet

**root**. En muchos labs introductorios, `root` sin contraseña es un error de configuración deliberado para enseñar el impacto.

## Metodología de explotación (paso a paso)

### 1. Confirmar que estás en la red del laboratorio

Tras conectar OpenVPN, comprueba que tienes interfaz `tun` o similar y rutas hacia `10.x.x.x` (según HTB).

### 2. `ping` al target

Valida conectividad L3 antes de perder tiempo en escaneos.

### 3. `nmap` al target

Identifica puertos abiertos. En Meow verás **23/tcp abierto** con servicio **telnet**.

### 4. Conexión Telnet

**Sintaxis general:**

```bash
telnet TARGET_IP 23
```

- `telnet`: cliente que negocia la sesión Telnet y te deja escribir como si fuera una consola remota.
- `TARGET_IP`: IP de la máquina Meow en tu VPN.
- `23`: puerto (opcional si es el predeterminado, pero es buena práctica indicarlo).

Cuando pida **login**, prueba `root`. Si pide **password**, deja vacío (solo Enter) si el laboratorio lo permite.

### 5. Obtener la flag de root

En máquinas Linux de HTB, la flag de *user/root* suele estar en un archivo tipo:

```bash
cat /root/root.txt
```

o en la ruta que indique el enunciado. `cat` concatena y muestra el contenido del archivo en la terminal.

**Otros comandos útiles en una shell limitada:**

- `whoami`: usuario actual (debería ser `root` si el login funcionó).
- `pwd`: directorio actual.
- `ls -la`: lista archivos con permisos y ocultos.

## Resumen de comandos usados

| Comando | Para qué sirve |
|--------|----------------|
| `openvpn --config archivo.ovpn` | Levantar VPN al laboratorio HTB |
| `ping` | Prueba ICMP de conectividad |
| `nmap` | Descubrimiento de puertos y servicios |
| `telnet IP 23` | Cliente Telnet al servicio del puerto 23 |
| `whoami` / `pwd` / `ls` / `cat` | Orientación y lectura de la flag en el sistema |

---

## Idea de defensa (por qué importa)

- **Telnet expuesto a Internet o a redes hostiles** filtra credenciales y órdenes en claro.
- **root accesible sin autenticación** es compromiso total del host.
- En entornos reales se usa **SSH** (cifrado) y **deshabilitación** de Telnet, además de políticas de contraseñas y segmentación.

## Checklist rápido

1. VPN OpenVPN conectada  
2. `ping` OK  
3. `nmap` → 23/tcp telnet  
4. `telnet` → usuario `root`, password vacía  
5. Leer flag (p. ej. `/root/root.txt`)
