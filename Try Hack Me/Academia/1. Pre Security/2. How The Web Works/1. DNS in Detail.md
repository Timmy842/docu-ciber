# 🌐 THM: DNS in Detail

> **Sala:** [DNS in Detail](https://tryhackme.com/room/dnsindetail)
> **Categoría:** Network Services
> **Concepto Clave:** El sistema jerárquico que traduce nombres de dominio (google.com) en direcciones IP (8.8.8.8).

---

## 📖 1. ¿Qué es DNS? (The Phonebook of the Internet)
DNS es un protocolo de la **Capa de Aplicación (Capa 7)** que elimina la necesidad de memorizar direcciones IP.

- **Funcionamiento básico:** Cuando escribes una URL, tu equipo pregunta a un servidor DNS: "¿Cuál es la IP de este dominio?". El servidor responde y tu navegador puede entonces establecer la conexión real.
- **Protocolo:** Utiliza principalmente **UDP** en el puerto **53** (por ser rápido), aunque puede usar TCP si los datos son muy grandes.

---

## 🌳 2. La Jerarquía de DNS
DNS no es una base de datos centralizada, sino una estructura de árbol invertido.



1.  **Root Domain (Nodo Raíz):** Representado por un punto `.` al final de los dominios (aunque no lo solemos escribir). Existen 13 clusters de servidores raíz en todo el mundo.
2.  **TLD (Top-Level Domain):** Son las extensiones de nivel superior.
    - *gTLD (Genéricos):* `.com`, `.org`, `.net`, `.edu`.
    - *ccTLD (Países):* `.es`, `.uk`, `.ca`.
3.  **Second-Level Domain:** El nombre que compramos (ej. `google` en `google.com`).
4.  **Subdomains:** Variaciones creadas por el dueño del dominio (ej. `blog.google.com`).

---

## 🛠️ 3. Tipos de Registros DNS (DNS Records)
Para que el sistema funcione, existen diferentes tipos de "entradas" en la base de datos DNS:

| Registro | Nombre Full | Función |
| :--- | :--- | :--- |
| **A** | Address | Mapea un nombre de dominio a una dirección **IPv4**. |
| **AAAA** | IPv6 Address | Mapea un nombre de dominio a una dirección **IPv6**. |
| **CNAME** | Canonical Name | Un alias. Apunta un dominio a otro dominio (ej. `www` -> `dominio.com`). |
| **MX** | Mail Exchange | Indica qué servidor gestiona los correos electrónicos del dominio. |
| **TXT** | Text | Almacena texto arbitrario. Se usa para verificar propiedad o configurar seguridad (SPF, DKIM). |
| **NS** | Name Server | Indica qué servidores son la autoridad oficial de ese dominio. |
| **SOA** | Start of Authority | Información sobre la zona DNS (administrador, tiempos de actualización). |

---

## 🔄 4. El Proceso de Resolución (Paso a Paso)
Cuando buscas `www.google.com`, ocurre lo siguiente en milisegundos:



1.  **DNS Recursive Resolver:** Tu PC pregunta a su resolver local (normalmente tu ISP o Google `8.8.8.8`).
2.  **Root Name Server:** Si el resolver no sabe la IP, le pregunta al servidor Raíz. El Raíz no sabe la IP, pero dice: "Ve a preguntar al servidor TLD de los `.com`".
3.  **TLD Name Server:** El servidor de los `.com` dice: "Yo no tengo la IP, pero ve a preguntar al servidor autoritativo de `google.com`".
4.  **Authoritative Name Server:** Este es el servidor final que tiene el registro **A**. Responde con la IP real (ej. `142.250.190.46`).
5.  **Caching:** El resolver guarda esta IP en su memoria por un tiempo determinado (**TTL - Time To Live**) para no repetir todo el proceso la próxima vez.

---

## 🔍 5. Herramientas de Diagnóstico
Para investigar registros DNS desde la terminal:

- **nslookup:** Herramienta básica.
  - `nslookup google.com` (Busca el registro A).
  - `nslookup -type=mx google.com` (Busca servidores de correo).
- **dig (Domain Information Groper):** Más potente y detallada.
  - `dig google.com`
  - `dig @8.8.8.8 google.com` (Pregunta a un servidor específico).

---

## 🛡️ Contexto de Ciberseguridad
- **DNS Poisoning / Cache Poisoning:** Inyectar entradas falsas en el cache de un servidor DNS para redirigir a los usuarios a sitios maliciosos.
- **DNS Exfiltration:** Técnica usada por malware para sacar datos de una red camuflándolos dentro de peticiones DNS (que suelen estar permitidas por los firewalls).
- **DNS Typosquatting:** Registrar dominios similares (ej. `g0ogle.com`) para engañar a usuarios.
