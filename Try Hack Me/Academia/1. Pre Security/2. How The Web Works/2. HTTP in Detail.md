## 1. Conceptos Fundamentales
- **HTTP (HyperText Transfer Protocol):** Protocolo de comunicación para transmitir datos en la web (HTML, imágenes, videos). Fue creado por Tim Berners-Lee.
- **HTTPS (HTTP Secure):** Versión segura que utiliza cifrado para proteger los datos y garantizar que el servidor es quien dice ser.

## 2. Anatomía de una URL
Una **URL** (Uniform Resource Locator) es la instrucción sobre cómo acceder a un recurso.

| Componente | Descripción |
| :--- | :--- |
| **Scheme** | Protocolo usado (http, https, ftp). |
| **User** | Credenciales de autenticación (poco común hoy en día). |
| **Host** | Dominio o IP del servidor. |
| **Port** | Puerto de conexión (80 para HTTP, 443 para HTTPS). |
| **Path** | Ruta específica del archivo o recurso. |
| **Query String** | Parámetros extra (ej: `?id=1`). |
| **Fragment** | Referencia a una sección interna de la página (`#seccion`). |

---

## 3. Peticiones y Respuestas

### 📥 Petición (Request)
Es lo que el cliente (navegador) envía al servidor.
- **Línea de solicitud:** Método + Ruta + Versión (Ej: `GET /index.html HTTP/1.1`).
- **Cabeceras clave:**
	- `Host`: Dominio del servidor.
	- `User-Agent`: Información del navegador y S.O.
	- `Referer`: URL de la página previa.

### 📤 Respuesta (Response)
Es lo que el servidor devuelve al cliente.
- **Línea de estado:** Versión + Código de estado (Ej: `HTTP/1.1 200 OK`).
- **Cabeceras clave:**
	- `Server`: Software del servidor (Apache, Nginx).
	- `Content-Type`: Tipo de contenido (text/html, image/png).
	- `Content-Length`: Tamaño del archivo en bytes.

---

## 4. Métodos HTTP (Verbos)
Definen la acción que se quiere realizar:
- **GET:** Solicitar datos del servidor (solo lectura).
- **POST:** Enviar datos para crear un nuevo recurso (ej: registros).
- **PUT:** Actualizar un recurso existente con datos nuevos.
- **DELETE:** Eliminar un recurso específico.

---

## 5. Códigos de Estado (Status Codes)

> [!TIP] Rangos de Códigos
> - **1xx:** Información (Petición recibida).
> - **2xx:** Éxito (Ej: `200 OK`, `201 Created`).
> - **3xx:** Redirección (Ej: `301 Moved Permanently`).
> - **4xx:** Error del Cliente (Ej: `404 Not Found`).
> - **5xx:** Error del Servidor (Ej: `500 Internal Server Error`).

| Código | Significado |
| :--- | :--- |
| **200** | Todo correcto. |
| **301/302** | Redirección permanente o temporal. |
| **401** | No autorizado (falta login). |
| **403** | Prohibido (no tienes permisos). |
| **405** | Método no permitido (ej: POST en una ruta de solo lectura). |
| **503** | Servicio no disponible (servidor caído o saturado). |

## 6. Cabeceras y Cookies 🍪

### Cabeceras Comunes
- **Accept-Encoding:** Formatos de compresión que entiende el cliente (gzip).
- **Cache-Control:** Instrucciones sobre cuánto tiempo guardar la página en caché.

### Gestión de Cookies
Dado que HTTP es **stateless** (no guarda estado entre peticiones), se usan cookies para recordar al usuario.
1. El servidor envía la cabecera `Set-Cookie: ID=123`.
2. El navegador la almacena localmente.
3. En cada petición futura, el navegador envía automáticamente `Cookie: ID=123`.
