## 1. Conceptos Generales
Cuando visitas un sitio web, tu navegador (cliente) realiza una petición a un servidor. El servidor responde con datos que el navegador renderiza para mostrar la página.

Existen dos componentes principales:
- **Front End (Client-Side):** Todo lo que el usuario ve y con lo que interactúa en el navegador.
- **Back End (Server-Side):** El servidor que procesa las peticiones y devuelve la información necesaria.

---

## 2. Tecnologías del Front-End
Un sitio web moderno se construye principalmente con tres lenguajes:

| Lenguaje | Función | Analogía |
| :--- | :--- | :--- |
| **HTML** | Define la estructura y el contenido. | El esqueleto. |
| **CSS** | Define el estilo y la apariencia (colores, fuentes). | La piel y ropa. |
| **JavaScript** | Añade interactividad y funciones complejas. | Los músculos y cerebro. |

### 🏗️ HTML (HyperText Markup Language)
Se basa en **etiquetas (tags)** que indican al navegador cómo mostrar el contenido.
- Estructura básica: `<html>`, `<head>`, `<body>`.
- Elementos comunes: `<h1>` (títulos), `<p>` (párrafos), `<img>` (imágenes), `<a>` (enlaces).
- **Atributos:** Proporcionan info extra (ej: `src` para imágenes o `id`/`class` para identificar elementos).

### ⚡ JavaScript (JS)
Permite que las páginas sean dinámicas. Se puede incluir directamente en el código o cargar desde archivos externos (`.js`).
- **Manipulación del DOM:** Permite cambiar el contenido de la página en tiempo real (ej: `document.getElementById("demo").innerHTML = "Texto cambiado";`).
- **Eventos:** Acciones que disparan código JS, como `onclick` (hacer clic en un botón) o `onhover` (pasar el ratón por encima).

## 3. Vulnerabilidades Básicas (Seguridad Web)

> [!WARNING] Exposición de Datos Sensibles (Sensitive Data Exposure)
> Ocurre cuando un desarrollador olvida eliminar información confidencial en el código fuente del Front-End. 
> **Práctica recomendada:** Siempre revisar el "Source Code" (Ctrl + U) buscando:
> - Comentarios con contraseñas temporales.
> - Enlaces a paneles de administración ocultos.
> - Claves de API o rutas de archivos privados.

> [!DANGER] Inyección de HTML (HTML Injection)
> Es una vulnerabilidad que ocurre cuando una web no "sanea" la entrada del usuario. 
> - **El problema:** Si el sitio muestra lo que un usuario escribe sin filtrar, el atacante puede introducir sus propias etiquetas HTML.
> - **Ejemplo de ataque:** Introducir `<a href="http://hacker.com">Haz clic aquí</a>` en un formulario de nombre para engañar a otros usuarios.
> - **Solución:** Sanitización de inputs (eliminar o escapar caracteres especiales como `< >`).

## 🛠 Notas de Metodología (Cheat Sheet)
- **Ver código fuente:** `Ctrl + U` o clic derecho -> "View Page Source".
- **Inspeccionar elementos:** `F12` o `Ctrl + Shift + I` para ver el DOM en tiempo real y probar inyecciones.
- **Regla de oro:** Nunca confíes en la entrada del usuario (*Never trust user input*).
