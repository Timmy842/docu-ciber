## 🏗️ 1. El Modelo TCP/IP vs OSI
Aunque el Modelo OSI (7 capas) es excelente para la teoría académica, el mundo real (Internet) funciona con el **Modelo TCP/IP** (4 capas). Esta sala se centra en cómo este modelo empaqueta los datos paso a paso.

### Comparativa y Mapeo
| Capa TCP/IP | Nombre | Capas OSI Equivalentes | Protocolos Comunes |
| :--- | :--- | :--- | :--- |
| **4. Application** | Aplicación | Application, Presentation, Session | HTTP, FTP, DNS, SMTP, SSH |
| **3. Transport** | Transporte | Transport | **TCP** (fiable), **UDP** (rápido) |
| **2. Internet** | Internet | Network | **IP** (IPv4, IPv6), ICMP, IPsec |
| **1. Network Interface** | Acceso a Red | Data Link, Physical | Ethernet, Wi-Fi, MAC Addresses |

> [!NOTE] **Concepto Clave: Encapsulación (Matryoshka)**
> Imagina una muñeca rusa.
> 1. Los datos de la App se meten dentro de una caja **TCP/UDP**.
> 2. Esa caja se mete dentro de una caja **IP**.
> 3. Esa caja se mete dentro de una caja **Ethernet**.
> 
> Al final, lo que viaja por el cable es una **Trama (Frame)**, que lleva dentro un **Paquete (Packet)**, que lleva dentro un **Segmento**.

## 🖼️ 2. Capa de Acceso a Red: La Trama Ethernet (Layer 2)
Aquí es donde los datos tocan el "metal" (el cable o la onda de radio). La unidad de datos es la **Trama (Frame)**.

### Estructura Detallada de la Trama Ethernet
Una trama tiene una estructura rígida para asegurar la entrega física.

`| PREAMBLE | SFD | DEST MAC | SRC MAC | TYPE | PAYLOAD (DATA) | FCS |`

#### Desglose de Campos:
1.  **Preamble (Preámbulo):**
    * *Función:* Es el "timbre" de la puerta. Una serie de 0s y 1s alternos para sincronizar el reloj del receptor.
    * *Detalle:* Le dice a la tarjeta de red: "¡Despierta, viene información!".
2.  **SFD (Start Frame Delimiter):**
    * *Función:* Marca el final del preámbulo y el inicio exacto de la trama.
3.  **Destination MAC Address:**
    * *Importancia:* La dirección física de la tarjeta de red (NIC) a la que va dirigido el mensaje.
    * *Nota:* Si es `FF:FF:FF:FF:FF:FF`, es un mensaje **Broadcast** (para todos).
4.  **Source MAC Address:**
    * *Importancia:* La dirección física de quien envía el mensaje (para saber a quién responder).
5.  **EtherType (Tipo):**
    * *Función:* Indica qué tipo de protocolo hay *dentro* de la carga útil.
    * *Ejemplo:* ¿Es un paquete IPv4? ¿Es IPv6? ¿Es ARP? El receptor necesita saber esto para pasarlo al software correcto superior.
6.  **Payload (Carga Útil):**
    * *Contenido:* Aquí viaja el **Paquete IP**. Es el "contenido real" que estamos transportando.
7.  **FCS (Frame Check Sequence):**
    * *Función:* Integridad de datos. Utiliza un algoritmo (CRC - Cyclic Redundancy Check).
    * *Proceso:* El emisor calcula un número basado en los datos. El receptor hace el mismo cálculo. Si los números no coinciden, la trama se corrompió en el cable y se descarta automáticamente.

## ✉️ 3. Capa de Internet: El Paquete IP (Layer 3)
Una vez que la tarjeta de red abre la trama y ve que es para ella, extrae el **Paquete IP**. Aquí nos movemos con direcciones lógicas (IPs) y enrutamiento global.

### Estructura Detallada del Header IPv4
El encabezado IP es como el sobre de una carta postal. Contiene la información para los routers.

```text
[ VER | IHL | TOS | TOTAL LENGTH ]
[ ID | FLAGS | FRAGMENT OFFSET ]
[ TTL | PROTOCOL | HEADER CHECKSUM ]
[ SOURCE IP ADDRESS ]
[ DESTINATION IP ADDRESS ]
[ OPTIONS (if any) ]
[ DATA (TCP/UDP Segment) ]
```

### 🔍 Desglose Técnico Extenso: Campos Críticos (Capa 3 y 4)

Para entender la ciberseguridad, no basta con saber qué es una IP; hay que entender qué hace cada bit del encabezado, porque ahí es donde los atacantes manipulan el tráfico.

#### A. Detalles del Paquete IP (Layer 3 - Internet)



1.  **TTL (Time to Live) - El "Seguro de Vida":**
    * **Funcionamiento:** Es un valor de 8 bits. Cada vez que el paquete pasa por un router (salto), el router resta 1 al valor. Si llega a 0, el router descarta el paquete y envía un mensaje ICMP "Time Exceeded" al origen.
    * **Uso en Hacking:** Herramientas como `traceroute` funcionan manipulando el TTL (enviando paquetes con TTL=1, luego TTL=2, etc.) para forzar a cada router del camino a identificarse.
    * **OS Fingerprinting:** Windows suele iniciar con TTL 128, Linux con 64. Ver el TTL de un paquete entrante te da una pista de qué sistema operativo tiene el objetivo.

2.  **Fragmentación (Flags y Fragment Offset):**
    * **Campos:** `Identification`, `Flags` (DF - Don't Fragment, MF - More Fragments) y `Fragment Offset`.
    * **Por qué importa:** Si un paquete es demasiado grande para un enlace (MTU), se divide. 
    * **Ataques:** Los atacantes usan la fragmentación para evadir Firewalls e IDS (Sistemas de Detección de Intrusos), enviando trozos de código malicioso por separado que solo se ensamblan al llegar al destino.

3.  **Protocol (8 bits):**
    * Indica al receptor qué protocolo de transporte sigue.
    * **Valores críticos:** * `06` (TCP)
        * `17` (UDP)
        * `01` (ICMP)
    * Si cambias este valor manualmente (Packet Crafting), el receptor no sabrá cómo procesar los datos.

---

#### B. Detalles del Segmento TCP (Layer 4 - Transporte)



El encabezado TCP es mucho más complejo porque gestiona el estado de la conexión.

1.  **Puertos (Source & Destination Ports):**
    * Son los "puntos finales" de la comunicación.
    * **Puertos bien conocidos (0-1023):** 21 (FTP), 22 (SSH), 80 (HTTP), 443 (HTTPS).
    * **Puertos efímeros:** Puertos aleatorios altos que usa tu PC para recibir la respuesta.

2.  **Sequence Number (Nº de Secuencia):**
    * TCP divide los datos en trozos. Este número le dice al receptor en qué posición va ese trozo.
    * **Importancia:** Permite reconstruir el archivo original aunque los paquetes lleguen desordenados por internet.

3.  **Flags (Banderas de Control) - El "Lenguaje" de la Red:**
    Aquí es donde ocurre la magia del análisis de red:
    * **SYN (Synchronize):** Inicio de conexión.
    * **ACK (Acknowledgment):** Confirmación de datos recibidos.
    * **PSH (Push):** Envía los datos al buffer de la aplicación inmediatamente.
    * **URG (Urgent):** Los datos son prioritarios.
    * **RST (Reset):** Corta la conexión de golpe (frecuente cuando intentas conectar a un puerto que está cerrado).
    * **FIN (Finish):** Cierre de conexión ordenado.

> [!DANGER] **Escaneos de Red (Nmap)**
> Cuando haces un escaneo de puertos, estás manipulando estas Flags. Por ejemplo, un "Stealth Scan" envía un SYN; si el servidor responde SYN/ACK, el puerto está abierto. Si responde RST, está cerrado.

#### C. El Proceso de Encapsulación Completo (Visión Técnica)



Para tu Obsidian, visualiza el flujo de datos así:

1.  **Datos (App):** "Hola Mundo"
2.  **Segmento (Capa 4):** [Header TCP (Puerto 80)] + "Hola Mundo"
3.  **Paquete (Capa 3):** [Header IP (IP Origen/Dest)] + [Header TCP] + "Hola Mundo"
4.  **Trama (Capa 2):** [Header Ethernet (MAC Origen/Dest)] + [Paquete IP] + [FCS (Error Check)]
5.  **Bits (Capa 1):** `01001000 01101111 01101100 01100001...` (Enviado por el cable).
