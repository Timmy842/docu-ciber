## 📝 Task 1: Introducción a las Shells de Linux
Una **shell** es un programa que actúa como interfaz entre el usuario y el sistema operativo (OS). Mientras que la interfaz gráfica (GUI) permite interactuar con el sistema a través de clics, la interfaz de línea de comandos (CLI) o shell interpreta tus comandos de texto y los pasa al OS para su ejecución. En el mundo de la ciberseguridad, el dominio de la CLI es esencial por su rapidez, menor consumo de recursos y enorme capacidad de automatización.

---

## 💻 Task 2: ¿Cómo interactuar con una Shell?
Al abrir una terminal en Linux, te recibe un *prompt* esperando instrucciones. En la mayoría de las distribuciones de Linux, la shell por defecto es **Bash** (Bourne Again Shell).

**Comandos básicos de interacción:**
* **`echo $SHELL`**: Muestra la ruta de la shell que estás utilizando actualmente (ej. `/bin/bash`).
* **`pwd`** (*Print Working Directory*): Muestra la ruta absoluta del directorio en el que te encuentras actualmente.
* **`cd <directorio>`** (*Change Directory*): Cambia tu ubicación al directorio especificado (ej. `cd Desktop`).
* **`ls`**: Lista el contenido (archivos y carpetas) del directorio actual.
* **`grep <patrón> <archivo>`**: Busca palabras específicas o patrones de texto dentro de un archivo (muy útil para encontrar *flags* ocultas en logs).

## 🐚 Task 3: Tipos de Shells en Linux
Existen diferentes tipos de shells, cada una con características particulares que mejoran la experiencia del usuario o añaden funcionalidades:
* **Bash (*Bourne Again Shell*)**: La más común y el estándar en la mayoría de distros. No tiene corrección ortográfica automática por defecto.
* **Fish (*Friendly Interactive Shell*)**: Diseñada para ser intuitiva y amigable. Destaca por tener **resaltado de sintaxis** (*syntax highlighting*) y auto-sugerencias de forma nativa.
* **Zsh (*Z Shell*)**: Muy popular entre desarrolladores y pentesters. Ofrece características avanzadas como **corrección ortográfica automática** y una enorme capacidad de personalización (frecuentemente combinada con frameworks como *Oh My Zsh*).
* **Comando extra**: El comando `history` muestra todos los comandos ejecutados previamente en la sesión actual.

## 📜 Task 4: Scripting en la Shell y sus Componentes
El *Shell Scripting* consiste en escribir una serie de comandos en un archivo de texto para que la shell los ejecute secuencialmente. Es la base de la automatización en Linux.

**Conceptos y componentes clave:**
* **Shebang (`#!/bin/bash`)**: Es obligatoriamente la primera línea de cualquier script. Le indica al sistema operativo qué intérprete debe usar para ejecutar el código contenido en el archivo.
* **Permisos de ejecución**: Para que un script pueda correr por sí solo, el sistema debe reconocerlo como ejecutable. Los permisos se otorgan con el comando **`chmod +x <nombre_script>`**.
* **Variables**: Contenedores para almacenar datos en memoria (ej. asignar una ruta: `directory="/home/user"`).
* **Bucles (*Loops*)**: Funcionalidad de scripting que permite configurar tareas iterativas, ejecutando comandos repetidamente hasta que se cumpla una condición específica.

## 🔐 Task 5 & 6: Ejercicios Prácticos (Locker Script y Búsqueda)
En la fase práctica de la sala se aplican los conceptos de scripting en escenarios reales:
* **El script *Locker***: Un ejercicio de control de acceso lógico donde se debe analizar un script que solicita credenciales mediante variables de entrada. Para superarlo, hay que introducir los datos exactos que el código espera (Username: `John`, Company: `Tryhackme`, PIN: `7385`).
* **Automatización de búsqueda de Flags**: Uso de scripts y herramientas nativas para automatizar el filtrado de archivos. Por ejemplo, utilizar variables de directorio y el comando `cat` junto con `grep` para buscar la palabra clave "bird" dentro de un archivo extenso como `authentication.log` y descubrir el mensaje oculto.
