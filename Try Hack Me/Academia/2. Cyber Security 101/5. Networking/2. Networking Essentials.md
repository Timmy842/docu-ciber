## Introducción
Este apunte resume los conceptos clave de la sala "Networking Essentials" de TryHackMe. Forma parte de la ruta *Cyber Security 101* y es la segunda sala de la serie de redes (continuación de *Networking Concepts*). Se centra en los protocolos prácticos y vitales que permiten la configuración automática, la resolución de direcciones, el enrutamiento de paquetes y la resolución de problemas en red.
## 1. DHCP (Dynamic Host Configuration Protocol)
El protocolo DHCP permite la configuración de red automática para dispositivos cliente. Para que un dispositivo pueda acceder e interactuar correctamente en una red, DHCP le asigna:
- Dirección IP y máscara de subred.
- Router (Puerta de enlace o *Gateway*).
- Servidor DNS.

**El proceso DORA:**
DHCP opera en la Capa de Aplicación y asigna direcciones mediante un proceso de 4 pasos conocido como **DORA**:
1. **D**iscover (Descubrimiento): El cliente, al no tener IP, envía un paquete de difusión (*broadcast*) buscando si existe algún servidor DHCP en la red local. 
    * *IP de origen:* `0.0.0.0`
    * *IP de destino:* `255.255.255.255` (Dirección de broadcast global)
2. **O**ffer (Oferta): El servidor DHCP recibe la petición y responde ofreciendo una configuración de red y una dirección IP disponible.
3. **R**equest (Solicitud): El cliente responde al servidor aceptando formalmente usar la IP que le ha sido ofrecida.
4. **A**cknowledge (Reconocimiento): El servidor confirma la asignación y registra que esa IP está ahora en uso por la dirección MAC de ese cliente.

## 2. ARP (Address Resolution Protocol)
ARP actúa como el "puente" entre el direccionamiento lógico de la **Capa 3** (IP) y el direccionamiento físico de la **Capa 2** (MAC).
- **El problema:** Para que dos dispositivos se envíen datos en la misma red local (ej. a través de Ethernet o WiFi), la tarjeta de red necesita conocer la dirección MAC de destino, no solo la dirección IP.
- **Funcionamiento:** Si el PC conoce la IP de destino pero no su MAC, envía un **ARP Request** preguntando: *"¿Quién tiene la IP X.X.X.X? Por favor, envíame tu MAC"*.
- **Dirección de Broadcast MAC:** Esta solicitud se envía a todos los dispositivos en el segmento de red utilizando la dirección MAC de destino de broadcast: `ff:ff:ff:ff:ff:ff`.

## 3. ICMP y Resolución de Problemas (Troubleshooting)
ICMP (Internet Control Message Protocol) es un protocolo de Capa 3 que no se utiliza para enviar datos de usuario, sino para enviar mensajes de error e información operativa sobre la red. Es la base de las herramientas de diagnóstico:

* **Ping:**
    * Envía paquetes ICMP *Echo Request* (solicitud) y espera un *Echo Reply* (respuesta).
    * Sirve para comprobar la conectividad básica con un sistema objetivo ("saber si está encendido y accesible") y para medir el **RTT** (Round-Trip Time o tiempo de ida y vuelta).
* **Traceroute (Linux/macOS) / Tracert (Windows):**
    * Se utiliza para descubrir la ruta exacta (los "saltos" o *hops*) que toma un paquete a través de múltiples routers hasta llegar a su destino final.
    * **Cómo funciona:** Modifica el campo **TTL (Time To Live)** en la cabecera IP. Envía un paquete con TTL=1 (que muere en el primer router, el cual devuelve un error ICMP), luego TTL=2 (que muere en el segundo router), y así sucesivamente hasta que el TTL no llegue a cero y alcance el destino final.

## 4. Enrutamiento (Routing)
El enrutamiento es el mecanismo por el cual los paquetes de datos se reenvían entre diferentes redes (generalmente a través de routers de Capa 3) desde un origen hasta un destino.
- Los routers inspeccionan la dirección IP de destino y deciden por qué cable o interfaz enviar el paquete para que se acerque a su destino.
- Utilizan **protocolos de enrutamiento** para aprender dinámicamente las rutas. Como dato técnico y ejemplo, **EIGRP** (Enhanced Interior Gateway Routing Protocol) es un protocolo de enrutamiento avanzado, propietario de Cisco.

## 5. NAT (Network Address Translation)
La traducción de direcciones de red (NAT) es lo que permite que varios dispositivos dentro de una red privada local (como tu casa u oficina) se conecten a Internet utilizando una **única dirección IP pública**.
- **Funcionamiento (PAT - Port Address Translation):** Cuando tu teléfono (con una IP privada interna como `192.168.0.x`) navega por Internet, el router intercepta el paquete, cambia esa IP privada de origen por la IP pública del router, y registra la conexión. Para el exterior (Internet), parece que todas las peticiones provienen de un solo dispositivo (el router).
- **Capacidad de conexiones:** Para distinguir a qué dispositivo interno pertenece cada respuesta de Internet, el router asigna números de puertos distintos a cada conexión. Como TCP/UDP utilizan puertos de 16 bits, existen 65,536 puertos posibles. En consecuencia, un router doméstico teóricamente puede mantener aproximadamente **65,000** conexiones TCP simultáneas hacia el exterior con una sola IP pública.
