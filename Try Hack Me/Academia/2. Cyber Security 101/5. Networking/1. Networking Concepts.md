## Introducción
Este apunte resume los conceptos clave de la sala "Networking Concepts" de TryHackMe, la cual es la primera de una serie dedicada a los fundamentos y protocolos de redes. Abarca desde los modelos teóricos de comunicación hasta la aplicación práctica de conexiones por línea de comandos.

## 1. El Modelo OSI (Open Systems Interconnection)
El modelo OSI es un marco conceptual creado por la Organización Internacional de Normalización (ISO) que estandariza las funciones de un sistema de red en 7 capas abstractas. Comprender este modelo es vital para entender en qué nivel opera cada dispositivo o protocolo en ciberseguridad (ej. "switch de capa 3" o "firewall de capa 7").

La regla nemotécnica común en inglés para recordarlas de abajo a arriba es *"Please Do Not Throw Spinach Pizza Away"*.

* **Capa 1: Física (Physical Layer):** Se encarga de la conexión física entre dispositivos y la transmisión de bits (0s y 1s) a través de un medio. Ejemplos de medios: cables Ethernet, fibra óptica, bandas de radio WiFi (2.4 GHz, 5 GHz).
* **Capa 2: Enlace de Datos (Data Link Layer):** Permite la transferencia fiable de datos entre nodos en el *mismo segmento de red*. Define cómo se comunican los dispositivos localmente utilizando direcciones **MAC** (Media Access Control, de 6 bytes en formato hexadecimal). Ejemplos: Ethernet (802.3), WiFi (802.11).
* **Capa 3: Red (Network Layer):** Se encarga del enrutamiento (*routing*) y direccionamiento lógico entre *diferentes redes*. Encuentra el mejor camino para los paquetes de red. Ejemplos: Protocolo IP, ICMP, IPSec (VPNs).
* **Capa 4: Transporte (Transport Layer):** Gestiona la comunicación de extremo a extremo entre aplicaciones corriendo en diferentes hosts. Se encarga de la segmentación y puede ofrecer control de flujo y corrección de errores. Protocolos clave: **TCP** y **UDP**.
* **Capa 5: Sesión (Session Layer):** Establece, mantiene y sincroniza la comunicación (sesiones) entre aplicaciones. Asegura la recuperación en caso de fallos de transmisión. Ejemplos: NFS, RPC.
* **Capa 6: Presentación (Presentation Layer):** Prepara, traduce (encoding), comprime y cifra los datos para que la capa de aplicación los entienda. Ejemplos: ASCII, Unicode, JPEG, MIME.
* **Capa 7: Aplicación (Application Layer):** Proporciona servicios de red y protocolos que interactúan directamente con las aplicaciones del usuario final. Ejemplos: HTTP, FTP, DNS, SMTP, IMAP.

## 2. El Modelo TCP/IP
Desarrollado en los años 70 por el Departamento de Defensa de EE. UU. (DoD), es un modelo práctico e implementado, diseñado específicamente para ser resiliente a fallos en la red. Tradicionalmente se agrupa en 4 capas, que mapean el modelo OSI de la siguiente manera:

1.  **Capa de Aplicación (Application Layer):** Agrupa las capas 5, 6 y 7 del modelo OSI. (Protocolos: HTTP, FTP, SSH, SMTP).
2.  **Capa de Transporte (Transport Layer):** Equivale a la capa 4 del OSI. (Protocolos: TCP, UDP).
3.  **Capa de Internet (Internet Layer):** Equivale a la capa 3 (Red) del OSI. (Protocolos: IP, ICMP).
4.  **Capa de Enlace (Link Layer):** Agrupa las capas 1 y 2 del OSI. (Protocolos: Ethernet, WiFi).

*(Nota: Muchos textos académicos modernos como el de Kurose y Ross lo dividen en 5 capas, separando la capa de Enlace y la Física al igual que en OSI).*

## 3. Direcciones IP, Subredes y Enrutamiento
* **Dirección IPv4:** Identificador único necesario para que un host sea encontrado en la red sin ambigüedades. Está compuesta por 32 bits divididos en 4 octetos (ej. `192.168.1.1`), permitiendo valores de 0 a 255 por octeto.
* **Direcciones Reservadas:** Por lo general, en una subred, la dirección terminada en `.0` identifica a la red misma, mientras que la `.255` es la dirección de *broadcast* (usada para enviar datos a todos los hosts de esa subred al mismo tiempo).
* **IP Privada vs Pública:** Debido a la limitación de direcciones IPv4 (aprox. 4 mil millones), se definieron rangos de IPs privadas para uso interno (hogares, oficinas) que no son enrutables en Internet.
    * *Rangos Privados comunes:* `10.x.x.x`, `172.16.x.x - 172.31.x.x`, `192.168.x.x`.
    * Para que un dispositivo con IP privada acceda a Internet, el router utiliza una IP Pública y aplica **NAT** (Network Address Translation).
* **Enrutamiento (Routing):** Un router es como una oficina de correos. Opera en la Capa 3, inspeccionando la dirección IP de destino de los paquetes de datos y reenvíandolos al mejor camino posible para que lleguen a la red correcta.

## 4. Protocolos UDP y TCP (Capa de Transporte)
Una vez que el protocolo IP localiza el host de destino, la capa de transporte utiliza **puertos** (números del 1 al 65535) para dirigir los datos al proceso o aplicación específica correcta.

* **UDP (User Datagram Protocol):**
    * Es un protocolo **no orientado a conexión** (*connectionless*).
    * No establece conexión previa y no garantiza ni confirma la entrega de los paquetes.
    * Ventaja: Es más rápido y requiere menos sobrecarga (*overhead*). Ideal para streaming de video, DNS o juegos online.
* **TCP (Transmission Control Protocol):**
    * Es un protocolo **orientado a conexión** (*connection-oriented*).
    * Utiliza un mecanismo de saludo de tres vías (*three-way handshake*) para establecer una sesión estable antes de transmitir.
    * Ventaja: Garantiza la entrega fiable y el orden exacto de los paquetes. Si un paquete se pierde, lo retransmite. Ideal para navegación web (HTTP), correos o transferencias de archivos.

## 5. Encapsulación de Datos
El ciclo de vida de un paquete en una red moderna implica un proceso de encapsulación (capa por capa) para el envío, y desencapsulación en el destino:
1.  **Capa de Aplicación:** Se generan los datos crudos (ej. petición de búsqueda en una web).
2.  **Capa de Transporte:** Se añade la cabecera (header) TCP o UDP con los puertos de origen y destino.
3.  **Capa de Internet (IP):** Se añade la cabecera IP con las direcciones IP de origen y destino, formando un *paquete IP*.
4.  **Capa de Enlace:** Se añade una cabecera y un tráiler con las direcciones MAC, creando un *frame/trama* que se transmite físicamente por WiFi o cable.
Los routers intermedios desencapsulan hasta la capa de Internet para leer la IP y enrutar, y el servidor de destino desencapsula completamente todas las capas para procesar la petición original.

## 6. Práctica: Uso de Telnet
* **TELNET:** Es un protocolo de red (y cliente de línea de comandos) para conexiones de terminal remotas sobre TCP. Es extremadamente útil para "hablar" en texto plano con cualquier servicio que esté escuchando en un puerto TCP.
* **Ejemplos prácticos:**
    * `telnet [IP] 7` (Conecta a un servidor *Echo*, el cual repite exactamente todo lo que escribes).
    * `telnet [IP] 13` (Conecta a un servidor *Daytime*, devuelve la fecha/hora actual del servidor y cierra la conexión).
    * `telnet [IP] 80` (Conecta a un servidor HTTP web. Permite interactuar manualmente simulando ser un navegador enviando, por ejemplo: `GET / HTTP/1.1` seguido de un doble Enter).
* *Nota de seguridad:* Protocolos en texto plano como Telnet o servidores como Echo/Daytime se consideran riesgos de seguridad hoy en día, ya que son susceptibles a interceptación de tráfico (sniffing), y se utilizan aquí estrictamente con fines educativos para entender la comunicación TCP.
