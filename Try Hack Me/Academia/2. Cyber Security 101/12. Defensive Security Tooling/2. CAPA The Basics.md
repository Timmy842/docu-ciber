# CAPA: The Basics

Este módulo introduce **CAPA**, una herramienta de análisis estático diseñada para identificar las "capacidades" (capabilities) de un archivo ejecutable. Es fundamental para el análisis de malware, ya que permite entender qué puede hacer un programa (e.g., comunicarse por red, manipular archivos, inyectar procesos) sin necesidad de ingeniería inversa manual profunda.

## Task 1: Introduction (Introducción)

**¿Qué es CAPA?**
Es una herramienta de código abierto desarrollada por Mandiant (ahora parte de Google Cloud). Su objetivo es detectar capacidades en archivos ejecutables (PE, ELF, .NET) basándose en un conjunto de reglas.
- **Función principal:** Analiza el archivo y aplica reglas que describen comportamientos comunes.
- **Beneficio:** Encapsula años de conocimiento de ingeniería inversa, permitiendo a los analistas (incluso principiantes) identificar rápidamente funcionalidades maliciosas.

## Task 2: Tool Overview: How CAPA Works (Visión General de la Herramienta)

CAPA se ejecuta principalmente desde la línea de comandos (CLI).

**Comandos y Parámetros Clave:**
- `capa <archivo>`: Ejecuta el análisis básico sobre el archivo especificado.
- `-h`: Muestra la ayuda y lista todos los parámetros disponibles.
- `-v`: (Verbose) Muestra información detallada sobre las capacidades encontradas.
- `-vv`: (Very Verbose) Muestra información muy detallada, incluyendo las direcciones de memoria donde se encontraron las coincidencias.

**Salida del Comando:**
El resultado incluye tablas con:
1.  Hashes del archivo (MD5, SHA1, SHA256).
2.  Mapeos a frameworks como MITRE ATT&CK y MBC.
3.  Lista detallada de las capacidades detectadas.

## Task 3: Dissecting CAPA Results Part 1: General Information, MITRE and MAEC (Disección de Resultados Parte 1)

El análisis de CAPA se divide en varios bloques de información:

### 1. General Information
Muestra metadatos básicos del archivo:
- **Hashes:** MD5, SHA1, SHA256 (útiles para buscar en VirusTotal).
- **Analysis:** Tipo de análisis (e.g., `static`).
- **OS:** Sistema operativo objetivo (e.g., `windows`).
- **Format:** Formato del archivo (e.g., `pe`, `elf`).
- **Arch:** Arquitectura (e.g., `i386`, `amd64`).

### 2. MITRE ATT&CK
Mapea las capacidades encontradas a las tácticas y técnicas del framework MITRE ATT&CK.
- **Ejemplo:** `DEFENSE EVASION` -> `Obfuscated Files or Information [T1027]`.
- Ayuda a entender *qué* está tratando de lograr el atacante y *cómo*.

### 3. MAEC (Malware Attribute Enumeration and Characterization)
Es un lenguaje estructurado para describir atributos de malware. CAPA usa etiquetas MAEC para categorizar comportamientos.
- **Launcher:** Indica que el archivo activa mecanismos de persistencia o ejecuta otros programas.
- **Downloader:** Indica que el archivo descarga payloads o recursos adicionales de internet.

## Task 4: Dissecting CAPA Results Part 2: Malware Behavior Catalogue (Disección de Resultados Parte 2: MBC)

**¿Qué es el MBC (Malware Behavior Catalogue)?**
Es un catálogo de objetivos y comportamientos de malware, diseñado para apoyar el análisis y reporte. A diferencia de ATT&CK (que se enfoca en adversarios en general), MBC se centra específicamente en malware.

**Estructura del MBC:**
- **Objective:** Basado en tácticas de ATT&CK (e.g., "Anti-Behavioral Analysis").
- **Behavior:** Comportamiento específico (e.g., "Virtual Machine Detection").
- **Micro-behaviors:** Acciones de bajo nivel que no son necesariamente maliciosas por sí mismas, pero que el malware usa (e.g., "Create Process", "Allocate Memory", "HTTP Communication").

**Identificadores:**
- Los comportamientos tienen IDs (e.g., `B0009` para Virtual Machine Detection).
- Los micro-comportamientos tienen IDs (e.g., `C0017` para Create Process).

## Task 5: Dissecting CAPA Results Part 3: Namespaces (Disección de Resultados Parte 3: Espacios de Nombres)

CAPA organiza sus reglas en "Namespaces" (espacios de nombres) jerárquicos para agrupar funcionalidades similares.
Formato: `Top-Level Namespace (TLN) / Sub-namespace`.

**Top-Level Namespaces (TLN) Comunes:**
1.  **anti-analysis:** Reglas para detectar técnicas de evasión, ofuscación, empaquetado (packing) y anti-debugging.
    - Ejemplo: `anti-analysis/anti-vm/vm-detection`.
2.  **host-interaction:** Reglas relacionadas con la interacción con el sistema anfitrión (archivos, procesos, registro, red).
3.  **persistence:** Reglas sobre cómo el malware mantiene acceso en el sistema (e.g., llaves de registro `Run`, tareas programadas).
4.  **nursery:** Un área para reglas nuevas o en desarrollo ("staging ground") que aún no están pulidas.
5.  **communication:** Reglas sobre comunicación de red (HTTP, TCP, etc.).

## Task 6: Dissecting CAPA Results Part 4: Capability (Disección de Resultados Parte 4: Capacidades)

Las "Capabilities" son el núcleo de CAPA. Cada capacidad está definida por una regla escrita en formato **YAML**.

- **Reglas:** Archivos `.yml` que contienen la lógica de detección.
- **Nombres:** El nombre de la capacidad en la salida suele ser el nombre del archivo de la regla (con espacios en lugar de guiones).
    - Ejemplo: Regla `check-http-status-code.yml` -> Capacidad `check HTTP status code`.
- **Lógica:** Las reglas buscan patrones específicos:
    - Strings (cadenas de texto).
    - Bytes.
    - Llamadas a API (e.g., `RegOpenKeyEx` para interactuar con el registro).
    - Características de la estructura del archivo.

## Task 7: More Information, more fun! (Más Información)

**Salida JSON:**
- `-j`: Permite exportar los resultados en formato JSON para ser procesados por otras herramientas o scripts.

**CAPA Web Explorer:**
- Es una herramienta basada en navegador para explorar los resultados de CAPA de forma interactiva.
- Permite filtrar resultados y ver detalles de manera visual.
- Cuenta con una "Global Search Box" para buscar capacidades específicas rápidamente.

## Task 8: Conclusion (Conclusión)

CAPA es una herramienta poderosa para el triaje inicial y el análisis estático de malware. Permite a los analistas obtener una visión rápida de las capacidades de un sospechoso sin invertir horas en ingeniería inversa manual. Su integración con MITRE ATT&CK y MBC proporciona un contexto valioso para la inteligencia de amenazas.
