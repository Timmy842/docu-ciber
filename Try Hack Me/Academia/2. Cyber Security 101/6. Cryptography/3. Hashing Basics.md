# TryHackMe: Hashing Basics

Este documento es un resumen detallado de la sala "Hashing Basics" de TryHackMe. El objetivo es entender los fundamentos de las funciones hash, su importancia en la seguridad (integridad y almacenamiento de contraseñas) y cómo identificar y crackear hashes básicos.

## Task 1: Introduction (Introducción)

El **hashing** es el proceso de tomar una entrada de cualquier longitud (un archivo, una contraseña, un texto) y convertirla en una salida de longitud fija llamada **hash** o **digest**.

**Características Clave:**
1.  **Unidireccional (One-way):** Es computacionalmente fácil calcular el hash a partir de los datos, pero prácticamente imposible revertir el proceso para obtener los datos originales.
2.  **Determinista:** La misma entrada siempre producirá exactamente el mismo hash.
3.  **Efecto Avalancha:** Un cambio mínimo en la entrada (incluso un solo bit) cambia drásticamente todo el hash resultante, haciendo imposible predecir la relación entre la entrada y la salida.

## Task 2: Hash Functions (Funciones Hash)

Existen muchos algoritmos de hashing, cada uno con diferentes propiedades de seguridad y longitud de salida. La longitud del hash (digest) es fija para cada algoritmo, independientemente del tamaño de la entrada.

### Algoritmos Comunes:

| Algoritmo | Longitud (bits) | Caracteres (Hex) | Estado de Seguridad |
| :--- | :--- | :--- | :--- |
| **MD5** | 128 bits | 32 | **Obsoleto.** Vulnerable a colisiones. Rápido pero inseguro. |
| **SHA-1** | 160 bits | 40 | **Obsoleto.** Google demostró una colisión en 2017 (SHAttered). |
| **SHA-256** | 256 bits | 64 | **Seguro.** Estándar actual para muchas aplicaciones. |
| **SHA-512** | 512 bits | 128 | **Muy Seguro.** Usado en sistemas críticos. |

> **Nota:** Aunque MD5 y SHA-1 son inseguros para firmas digitales o certificados SSL (donde la resistencia a colisiones es crítica), siguen siendo útiles para verificaciones simples de integridad de archivos no críticos.

## Task 3: Insecure Password Storage for Authentication

Nunca se deben almacenar las contraseñas de los usuarios en **texto plano** (sin cifrar) en una base de datos. Si un atacante compromete la base de datos, tendría acceso inmediato a todas las cuentas.

La solución estándar es almacenar solo el **hash** de la contraseña.
- Cuando el usuario se registra: Se calcula el hash de su contraseña y se guarda en la DB.
- Cuando el usuario se loguea: Se calcula el hash de la contraseña ingresada y se compara con el hash almacenado.
- Si coinciden, la contraseña es correcta. El servidor nunca necesita saber la contraseña real.

## Task 4: Using Hashing for Secure Password Storage (Salting)

Incluso almacenando hashes, existe un problema: si dos usuarios tienen la misma contraseña (ej. "password123"), tendrán el mismo hash. Esto permite a los atacantes usar **Rainbow Tables** (tablas precalculadas de hashes de millones de contraseñas comunes) para revertir los hashes masivamente.

### Solución: Salting (Uso de "Sales")
Se añade un valor aleatorio único (**Salt**) a cada contraseña antes de hashearla.
- **Fórmula:** `Hash = Función(Contraseña + Salt)`
- El Salt se guarda en texto claro junto al hash en la base de datos.
- **Beneficio:** Incluso si dos usuarios tienen la misma contraseña, sus sales serán diferentes, por lo que sus hashes finales serán totalmente distintos. Esto inutiliza las Rainbow Tables, obligando al atacante a crackear cada hash individualmente.

## Task 5: Recognising Password Hashes (Identificar Hashes)

Para atacar un hash, primero debes saber qué algoritmo lo generó. La principal pista es la **longitud** y el conjunto de caracteres (generalmente hexadecimal: 0-9, a-f).

### Herramientas de Identificación:
1.  **Conteo de caracteres:**
    - 32 chars -> Probablemente MD5.
    - 40 chars -> Probablemente SHA-1.
    - 64 chars -> Probablemente SHA-256.
2.  **Prefijos:** Algunos hashes (como bcrypt o hash de Linux) tienen formatos específicos como `$1$`, `$2a$`, `$6$`.
3.  **Herramientas Automáticas:**
    - `hash-identifier` (Kali Linux)
    - `hashid` (Python tool)
    - Sitios web como [TunnelsUp Hash Analyzer](https://www.tunnelsup.com/hash-analyzer/).

## Task 6: Password Cracking (Cracking de Contraseñas)

Dado que los hashes no son reversibles, el "cracking" consiste en adivinar una contraseña, hashearla y comparar si coincide con el hash objetivo.

### Métodos de Ataque:
1.  **Ataque de Diccionario:** Probar palabras de una lista predefinida de contraseñas comunes (ej. `rockyou.txt`). Es rápido pero solo funciona si la contraseña es común.
2.  **Fuerza Bruta (Brute Force):** Probar todas las combinaciones posibles de caracteres (aaaa, aaab...). Garantiza encontrar la contraseña, pero puede tardar años o siglos dependiendo de la longitud y complejidad.
3.  **Híbrido:** Combinar diccionario con reglas (ej. probar "password" y añadirle números o símbolos al final).

### Herramientas Principales:
- **John the Ripper (JtR):** Versátil, soporta CPU, autodetecta formatos.
    ```bash
    john --wordlist=/usr/share/wordlists/rockyou.txt hashes.txt
    ```
- **Hashcat:** Extremadamente rápida, optimizada para GPU. Requiere especificar el modo del hash.
    ```bash
    hashcat -m 0 -a 0 hashes.txt rockyou.txt  # -m 0 es MD5
    ```

## Task 7: Hashing for Integrity Checking (Integridad)

El hashing es fundamental para verificar la integridad de los datos, asegurando que no han sido alterados (por error en la transmisión o por un atacante).

**Escenario Típico:** Descarga de Software.
1.  El desarrollador publica el archivo `.iso` o `.exe` en su web junto con su hash (MD5, SHA-256).
2.  Descargas el archivo.
3.  Calculas el hash localmente en tu máquina.
4.  Comparas tu hash con el publicado. Si coinciden, el archivo es auténtico e íntegro.

**Comandos en Linux:**
```bash
md5sum archivo.txt
sha256sum archivo.txt
```

## Task 8: Conclusion

El hashing es una herramienta versátil en ciberseguridad, esencial para:
- **Integridad:** Verificar que los archivos no han sido modificados.
- **Autenticación:** Almacenar contraseñas de forma segura (con Salting).
- **Forense:** Identificar archivos conocidos (malware o archivos de sistema) sin analizarlos completos.

Comprender sus fortalezas (unidireccionalidad) y debilidades (colisiones en algoritmos viejos, susceptibilidad a fuerza bruta si la entrada es débil) es crucial.
