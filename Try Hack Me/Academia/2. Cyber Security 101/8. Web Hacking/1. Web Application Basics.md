# TryHackMe: Web Application Basics

Este documento es un resumen detallado de la sala "Web Application Basics" de TryHackMe. En esta sala se exploran los elementos clave de una aplicación web, como URLs, peticiones HTTP y respuestas, fundamentales para entender cómo funcionan las aplicaciones web y su seguridad.

## Task 1: Introduction (Introducción)

Una aplicación web es un software al que se accede a través de un navegador web. Comprender sus componentes básicos es esencial para cualquier rol en ciberseguridad o desarrollo.

**Objetivos de Aprendizaje:**
- Entender qué es una aplicación web y cómo se ejecuta en el navegador.
- Desglosar los componentes de una URL.
- Aprender cómo funcionan las peticiones y respuestas HTTP.
- Familiarizarse con los métodos de petición HTTP.
- Entender los códigos de respuesta HTTP.
- Conocer las cabeceras HTTP y su importancia en seguridad.

## Task 2: Web Application Overview (Visión General)

Podemos imaginar una aplicación web como un planeta.
- **Superficie (Front End):** Lo que vemos y con lo que interactuamos (como astronautas explorando).
- **Interior (Back End):** Todo lo que sucede "bajo la superficie" para que el planeta funcione, invisible para el usuario promedio.

### Front End (El lado del Cliente)
Es la parte con la que el usuario interactúa en su navegador. Utiliza tecnologías clave:
1.  **HTML (Hypertext Markup Language):** La estructura y contenido. Es como el "ADN" básico o el esqueleto. Dice al navegador *qué* mostrar.
2.  **CSS (Cascading Style Sheets):** El diseño y apariencia. Define colores, fuentes y layout. Es lo que hace que el planeta se vea vibrante y bonito.
3.  **JavaScript (JS):** La interactividad y lógica. Es el "cerebro" que permite tomar decisiones y crear comportamientos complejos y dinámicos en la página.

### Back End (El lado del Servidor)
Son los componentes invisibles pero vitales:
1.  **Base de Datos (Database):** Donde se almacena, modifica y recupera la información (ej. preferencias de usuario, productos). Es como el ecosistema rico en recursos del planeta.
2.  **Infraestructura:** Servidores web, servidores de aplicaciones, redes y almacenamiento. Son las "carreteras" y sistemas de soporte.
3.  **WAF (Web Application Firewall):** Un componente de seguridad opcional que filtra peticiones maliciosas, protegiendo la aplicación como la capa de ozono protege al planeta.

## Task 3: Uniform Resource Locator (URL)

Una URL es la dirección web que permite acceder a recursos en internet (páginas, imágenes, videos).

**Anatomía de una URL:**
1.  **Esquema (Scheme):** El protocolo usado. `HTTP` o `HTTPS` (seguro, encriptado).
2.  **Usuario (User):** (Raro hoy en día) Credenciales de login en la URL. Inseguro.
3.  **Host/Dominio:** El nombre del sitio web (ej. `tryhackme.com`). Es crucial verificarlo para evitar phishing (typosquatting).
4.  **Puerto (Port):** La "puerta" de entrada al servidor. `80` para HTTP, `443` para HTTPS.
5.  **Ruta (Path):** La ubicación exacta del archivo o recurso en el servidor (ej. `/api/users`).
6.  **Query String:** Parámetros después del `?`. Se usan para búsquedas o filtros (ej. `?search=term`). Deben manejarse con cuidado para evitar inyecciones.
7.  **Fragmento (Fragment):** Después del `#`. Apunta a una sección específica de la página actual.

## Task 4: HTTP Messages (Mensajes HTTP)

La comunicación web se basa en el intercambio de paquetes de datos llamados mensajes HTTP.
- **HTTP Requests (Peticiones):** Enviadas por el cliente (usuario) para pedir algo o enviar datos.
- **HTTP Responses (Respuestas):** Enviadas por el servidor con el resultado.

**Estructura del Mensaje:**
1.  **Start Line (Línea de Inicio):** Define el tipo de mensaje (método y ruta para requests; código de estado para responses).
2.  **Headers (Cabeceras):** Pares clave-valor con metadatos (seguridad, tipo de contenido, etc.).
3.  **Empty Line:** Separa las cabeceras del cuerpo.
4.  **Body (Cuerpo):** Los datos reales (contenido de la página en respuestas, o datos de formulario en peticiones).

## Task 5: HTTP Request Methods (Métodos de Petición)

La línea de petición (`METHOD /path HTTP/version`) indica qué acción se quiere realizar.

**Métodos Comunes:**
- **GET:** Solicita datos. **Nota de seguridad:** No enviar información sensible en GET (queda en logs/historial).
- **POST:** Envía datos para crear/actualizar recursos. **Nota:** Validar siempre la entrada para prevenir inyecciones.
- **PUT:** Reemplaza o actualiza un recurso completo. Requiere autorización.
- **DELETE:** Elimina un recurso. Requiere autorización estricta.

**Otros Métodos:**
- **PATCH:** Actualización parcial.
- **HEAD:** Solo pide cabeceras (sin cuerpo).
- **OPTIONS:** Pregunta qué métodos están permitidos.
- **TRACE:** Loopback para debugging (riesgo de seguridad).
- **CONNECT:** Túnel para HTTPS.

**Versiones HTTP:**
- **HTTP/1.1:** Estándar actual más común (conexiones persistentes).
- **HTTP/2 & HTTP/3:** Más rápidos y seguros (multiplexación, QUIC), ganando adopción.

## Task 6: Request Headers & Body (Cabeceras y Cuerpo)

### Cabeceras Comunes (Request Headers)
Proporcionan contexto al servidor:
- **Host:** El dominio del servidor (ej. `tryhackme.com`).
- **User-Agent:** Información sobre el navegador/SO del cliente.
- **Referer:** La URL desde la que se hizo la petición.
- **Cookie:** Datos de sesión almacenados previamente por el navegador.
- **Content-Type:** Formato de los datos enviados (ej. `application/json`).

### Cuerpo de la Petición (Request Body)
Usado en `POST` y `PUT` para enviar datos. Formatos comunes:
1.  **URL Encoded (`application/x-www-form-urlencoded`):** Pares clave-valor (`key1=value1&key2=value2`).
2.  **Form Data (`multipart/form-data`):** Para subir archivos o datos binarios. Usa "boundaries" para separar partes.
3.  **JSON (`application/json`):** Estructura de datos moderna y ligera (`{"name": "Alex", "age": 27}`).
4.  **XML (`application/xml`):** Estructura basada en etiquetas (`<user><name>Alex</name></user>`).

## Task 7: Response Status Codes (Códigos de Estado)

Cuando el servidor responde, incluye una línea de estado con la versión HTTP, un código numérico de 3 dígitos y una frase explicativa (Reason Phrase).

### Categorías de Códigos:
- **1xx (Informativos):** El servidor recibió la petición y continúa el proceso (ej. `100 Continue`).
- **2xx (Éxito):** La petición fue recibida y aceptada correctamente.
    - `200 OK`: Todo salió bien.
- **3xx (Redirección):** El recurso se ha movido.
    - `301 Moved Permanently`: Redirección permanente (nueva URL).
- **4xx (Error del Cliente):** Hubo un error en la petición del usuario.
    - `400 Bad Request`: Petición mal formada.
    - `404 Not Found`: Recurso no encontrado.
- **5xx (Error del Servidor):** El servidor falló al procesar una petición válida.
    - `500 Internal Server Error`: Error genérico en el servidor.

## Task 8: Response Headers (Cabeceras de Respuesta)

El servidor también envía cabeceras para decir al cliente cómo manejar la respuesta.

### Cabeceras Clave:
- **Date:** Fecha y hora de la respuesta.
- **Content-Type:** Tipo de contenido devuelto (ej. `text/html; charset=utf-8`).
- **Server:** Software del servidor (ej. `nginx`). A menudo se oculta por seguridad.
- **Set-Cookie:** Instruye al navegador para guardar una cookie.
    - **Flags de seguridad:** `HttpOnly` (no accesible por JS) y `Secure` (solo HTTPS).
- **Cache-Control:** Define cuánto tiempo se puede guardar la respuesta en caché.
- **Location:** Usado en redirecciones (3xx) para indicar la nueva URL.

### Response Body
El cuerpo contiene los datos solicitados (HTML, JSON, imágenes). **Nota de seguridad:** Siempre sanitizar los datos antes de mostrarlos para evitar XSS.

## Task 9: Security Headers (Cabeceras de Seguridad)

Estas cabeceras ayudan a mitigar ataques como XSS, Clickjacking, etc.

1.  **Content-Security-Policy (CSP):** Define desde qué dominios se pueden cargar recursos (scripts, estilos, imágenes).
    - `default-src 'self'`: Solo permite recursos del mismo dominio.
    - Ayuda a prevenir XSS al bloquear scripts maliciosos externos.
2.  **Strict-Transport-Security (HSTS):** Fuerza al navegador a usar siempre HTTPS.
    - `max-age`: Tiempo en segundos.
    - `includeSubDomains`: Aplica a subdominios.
3.  **X-Content-Type-Options:** `nosniff`. Impide que el navegador "adivine" el tipo de archivo, obligándolo a respetar el `Content-Type`.
4.  **Referrer-Policy:** Controla cuánta información se envía en la cabecera `Referer` al navegar a otro sitio.
    - `no-referrer`: No envía nada.
    - `same-origin`: Solo envía si es el mismo dominio.
