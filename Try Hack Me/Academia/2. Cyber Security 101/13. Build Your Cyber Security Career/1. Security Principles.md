# Security Principles

Este módulo cubre los principios fundamentales de seguridad que todo profesional debe conocer. No existe la seguridad perfecta, pero podemos mejorar nuestra postura de seguridad para dificultar el acceso a los adversarios.

## Task 1: Introduction

Antes de discutir los principios de seguridad, es vital conocer al adversario contra el cual estamos protegiendo nuestros activos.
-   **Conoce a tu enemigo**: ¿Estás protegiendo una laptop de un niño pequeño o de espías industriales? Los controles de seguridad deben ser proporcionales a la amenaza.
-   **No existe la seguridad al 100%**: El objetivo es mejorar la postura de seguridad para hacer más difícil que los adversarios obtengan acceso.

## Task 2: CIA Triad (La Tríada CIA)

El modelo CIA es la base para evaluar la seguridad de un sistema.

1.  **Confidentiality (Confidencialidad)**:
    -   Asegura que solo las personas o destinatarios autorizados puedan acceder a los datos.
    -   Ejemplo: En compras online, tu tarjeta de crédito solo debe ser visible para el procesador de pagos. En medicina, los historiales clínicos son confidenciales por ley.

2.  **Integrity (Integridad)**:
    -   Asegura que los datos no puedan ser alterados sin autorización y que cualquier alteración pueda ser detectada.
    -   Ejemplo: Si un intruso cambia la dirección de envío de tu pedido, el paquete se enviará a otro lugar. En medicina, un historial alterado puede llevar a un tratamiento incorrecto y peligroso.

3.  **Availability (Disponibilidad)**:
    -   Asegura que el sistema o servicio esté disponible cuando se necesite.
    -   Ejemplo: Si la tienda online está caída, no puedes comprar. Si el sistema médico no está disponible, el médico no puede consultar el historial del paciente.

### Más allá de la CIA

-   **Authenticity (Autenticidad)**: Asegurar que el documento/archivo/dato proviene de la fuente reclamada (no es fraudulento o falsificado).
-   **Nonrepudiation (No repudio)**: Asegurar que la fuente original no pueda negar que es la fuente de un documento/archivo/dato particular.

### Parkerian Hexad (El Hexágono de Parker)
Donn Parker propuso añadir dos elementos más:
-   **Utility (Utilidad)**: La información debe ser útil (si pierdes la clave de desencriptación, los datos son inútiles).
-   **Possession (Posesión/Control)**: Proteger la información de ser tomada, copiada o controlada sin autorización (ej. si roban un disco de respaldo, pierdes el control aunque tengas copia).

**Flag**: `THM{CIA_TRIAD}`

## Task 3: DAD Triad (La Tríada DAD)

El opuesto de la tríada CIA. Representa los ataques o fallos de seguridad.

1.  **Disclosure (Divulgación)** - Opuesto a Confidencialidad:
    -   Cuando alguien filtra información secreta.
    -   Ejemplo: Filtración de registros médicos en línea.

2.  **Alteration (Alteración)** - Opuesto a Integridad:
    -   Cuando alguien modifica datos sin permiso.
    -   Ejemplo: Modificar un cheque o un registro médico.

3.  **Destruction/Denial (Destrucción/Denegación)** - Opuesto a Disponibilidad:
    -   Cuando se interrumpe el acceso al sistema.
    -   Ejemplo: Apagar los sistemas de energía de un hospital o un ataque DDoS.

## Task 4: Fundamental Concepts of Security Models

Modelos clásicos para asegurar las funciones de seguridad.

### 1. Bell-LaPadula Model (Para Confidencialidad)
Se centra en mantener los secretos a salvo. Usado en entornos militares.
-   **Simple Security Property ("No Read Up")**: Un sujeto en un nivel de seguridad inferior no puede leer un objeto en un nivel superior.
-   **Star Security Property ("No Write Down")**: Un sujeto en un nivel superior no puede escribir en un objeto de nivel inferior (para evitar filtrar secretos a niveles bajos).

### 2. Biba Model (Para Integridad)
Se centra en asegurar que la información sea confiable y no sea alterada incorrectamente.
-   **Simple Integrity Property ("No Read Down")**: Un sujeto de mayor integridad no debe leer de un objeto de menor integridad (para no contaminarse con datos poco fiables).
-   **Star Integrity Property ("No Write Up")**: Un sujeto de menor integridad no debe escribir en un objeto de mayor integridad (para no corromper datos fiables).

### 3. Clark-Wilson Model (Para Integridad)
Usa conceptos como:
-   **CDI (Constrained Data Item)**: Datos que deben protegerse.
-   **UDI (Unconstrained Data Item)**: Datos no críticos.
-   **TPs (Transformation Procedures)**: Procedimientos permitidos para modificar CDIs.
-   **IVPs (Integrity Verification Procedures)**: Verifican la integridad de los datos.

**Flag**: `THM{SECURITY_MODELS}`

## Task 5: Defence-in-Depth (Defensa en Profundidad)

También llamado **Multi-Level Security**.
-   Consiste en crear un sistema de seguridad con múltiples capas.
-   Si una capa falla, las otras siguen protegiendo.
-   Ejemplo: Cerrar el cajón con llave, cerrar la habitación, cerrar la puerta principal, cerrar la verja del edificio, poner cámaras.
-   Incluye seguridad física, técnica y administrativa.

## Task 6: ISO/IEC 19249

Estándar que lista principios arquitectónicos y de diseño.

### 5 Principios Arquitectónicos
1.  **Domain Separation (Separación de Dominios)**: Agrupar componentes relacionados en una entidad o dominio único.
2.  **Layering (Capas)**: Estructurar el sistema en niveles abstractos para imponer políticas de seguridad en diferentes niveles.
3.  **Encapsulation (Encapsulamiento)**: Ocultar implementaciones de bajo nivel y prevenir manipulación directa de datos.
4.  **Redundancy (Redundancia)**: Asegurar disponibilidad e integridad mediante duplicidad.
5.  **Virtualization (Virtualización)**: Compartir hardware entre múltiples sistemas operativos (sandboxing).

### 5 Principios de Diseño
1.  **Least Privilege (Mínimo Privilegio)**: Dar solo los permisos necesarios para realizar la tarea y nada más.
2.  **Attack Surface Minimisation (Minimización de Superficie de Ataque)**: Reducir vulnerabilidades (ej. deshabilitar servicios no usados).
3.  **Centralized Parameter Validation (Validación Centralizada de Parámetros)**: Validar entradas en una librería o sistema central.
4.  **Centralized General Security Services (Servicios de Seguridad Centralizados)**: Centralizar autenticación, autorización, etc.
5.  **Preparing for Error and Exception Handling (Manejo de Errores)**: Diseñar para fallar de forma segura (fail-safe) y que los mensajes de error no filtren información.

## Task 7: Zero Trust versus Trust but Verify

### Trust but Verify (Confiar pero Verificar)
-   Modelo tradicional.
-   Se verifica la identidad una vez y luego se confía en el usuario dentro de la red.
-   Problema: Si un atacante entra, tiene vía libre (movimiento lateral fácil).

### Zero Trust (Cero Confianza)
-   **"Never trust, always verify"** (Nunca confíes, siempre verifica).
-   Trata la confianza como una vulnerabilidad.
-   Cada entidad se considera adversaria hasta que se demuestre lo contrario.
-   No otorga confianza basada en ubicación (estar dentro de la red) o propiedad.
-   Requiere autenticación y autorización continua para cada recurso.
-   Usa micro-segmentación.

## Task 8: Threat versus Risk

Es crucial entender la diferencia entre vulnerabilidad, amenaza y riesgo.

1.  **Vulnerability (Vulnerabilidad)**:
    -   Una debilidad o fallo en el sistema.
    -   Ejemplo: Una puerta de cristal en una tienda.

2.  **Threat (Amenaza)**:
    -   Un peligro potencial asociado con esa debilidad.
    -   Ejemplo: Alguien con una piedra que quiere romper el cristal.

3.  **Risk (Riesgo)**:
    -   La probabilidad de que una amenaza explote una vulnerabilidad y el impacto resultante en el negocio.
    -   **Riesgo = Probabilidad x Impacto**.
    -   Ejemplo: La probabilidad de que rompan el cristal y el coste de reemplazarlo + lo robado.

## Task 9: Conclusion

La seguridad es un proceso continuo de equilibrio entre la tríada CIA, aplicando defensa en profundidad y adoptando modelos modernos como Zero Trust para mitigar riesgos.
