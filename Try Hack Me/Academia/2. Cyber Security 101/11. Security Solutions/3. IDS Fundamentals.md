## Tarea 1: ¿Qué es un IDS?

### Concepto: La Cámara de Vigilancia de Red
Mientras que un Firewall actúa como un portero (bloqueando/permitiendo tráfico), un **Sistema de Detección de Intrusiones (IDS)** actúa como una cámara de seguridad dentro del edificio.
-   **Objetivo:** Detectar actividades maliciosas que podrían haber evadido el firewall o haberse originado desde dentro de la red.
-   **Operación:** Monitorea el tráfico, lo compara contra firmas conocidas o anomalías, y genera **alertas**.
-   **Limitación:** Un IDS estándar es una herramienta de monitoreo **pasiva**. *Detecta* y *alerta*, pero **no** detiene la amenaza (a diferencia de un IPS - Sistema de Prevención de Intrusiones).

**Preguntas:**
- **¿Puede un sistema de detección de intrusiones (IDS) prevenir la amenaza después de detectarla? Yea/Nay**
  - `Nay`

## Tarea 2: Tipos de IDS

Las soluciones de IDS se categorizan por modos de **Despliegue** y **Detección**.

### Modos de Despliegue
1.  **HIDS (Sistema de Detección de Intrusiones en Host):** Instalado en dispositivos individuales (hosts). Monitorea actividades internas (integridad de archivos, logs) de esa máquina específica.
2.  **NIDS (Sistema de Detección de Intrusiones en Red):** Colocado en puntos estratégicos en la red. Monitorea el tráfico que fluye a través de la red para detectar amenazas que afectan a múltiples hosts.

### Modos de Detección
1.  **Basado en Firmas:** Compara el tráfico contra una base de datos de patrones de ataque conocidos (firmas). Bueno para amenazas conocidas, malo para Días Cero (Zero-Days).
2.  **Basado en Anomalías:** Aprende el comportamiento base "normal" y alerta sobre desviaciones. Bueno para amenazas desconocidas, pero propenso a Falsos Positivos.
3.  **Híbrido:** Combina ambos métodos.

**Preguntas:**
- **¿Qué tipo de IDS se despliega para detectar amenazas en toda la red?**
  - `Network Intrusion Detection System`
- **¿Qué IDS aprovecha tanto las técnicas de detección basadas en firmas como las basadas en anomalías?**
  - `Hybrid IDS`

## Tarea 3: Ejemplo de IDS: Snort

### Concepto: Snort
**Snort** es un IDS/IPS de código abierto ampliamente utilizado. Tiene tres modos principales de operación:
1.  **Modo Packet Sniffer (Rastreador de Paquetes):** Lee y muestra paquetes de red en tiempo real (como tcpdump).
2.  **Modo Packet Logging (Registro de Paquetes):** Registra paquetes en el disco (usualmente en formato PCAP) para análisis posterior.
3.  **Modo NIDS:** El modo principal. Analiza el tráfico contra reglas definidas por el usuario para detectar intrusiones.

**Preguntas:**
- **¿Qué modo de Snort nos ayuda a registrar el tráfico de red en un archivo PCAP?**
  - `Packet Logging Mode`
- **¿Cómo se llama el modo principal de Snort?**
  - `Network Intrusion Detection System Mode`

## Tarea 4: Uso de Snort

### Estructura de Regla
Las reglas de Snort definen sobre qué tráfico alertar. Una regla consiste en un **Encabezado** (Acción, Protocolo, IP, Puerto) y **Opciones** (Metadatos en paréntesis).

*Estructura de Regla de Ejemplo:*
`acción protocolo ip_origen puerto_origen -> ip_destino puerto_destino (opciones)`

-   **Acción:** ej., `alert`, `log`, `pass`.
-   **Protocolo:** ej., `tcp`, `udp`, `icmp`.
-   **Rev:** Número de revisión de la regla (encontrado en opciones).
-   **Sid:** ID de Firma (identificador único).
-   **Msg:** El mensaje a mostrar cuando la regla se activa.

### Directorios
-   **Configuración:** `/etc/snort/snort.conf`
-   **Reglas:** `/etc/snort/rules/`
-   **Reglas Personalizadas:** `/etc/snort/rules/local.rules`

**Preguntas:**
- **¿Dónde está el directorio principal de Snort que almacena sus archivos?**
  - `/etc/snort`
- **¿Qué campo en la regla de Snort indica el número de revisión de la regla?**
  - `rev`
- **¿Qué protocolo se define en la regla de muestra creada en la tarea?**
  - `icmp` (Esto se refiere al ejemplo típicamente mostrado en la descripción de la tarea).
- **¿Cuál es el nombre del archivo que contiene reglas personalizadas para Snort?**
  - `local.rules`

## Tarea 5: Laboratorio Práctico

### Escenario: Investigando un PCAP
Se te da un archivo PCAP (`Task.pcap` o `Intro_to_IDS.pcap`) y se te encarga ejecutar Snort para investigar un ataque.

### Pasos de Investigación
1.  **Ejecutar Snort:** Comando para leer el pcap y usar la configuración:
    `sudo snort -r Task.pcap -c /etc/snort/snort.conf -A console`
2.  **Analizar Alertas:**
    -   **Conexión SSH:** Ves una alerta por un intento de conexión SSH.
    -   **IP de Origen:** El log muestra la IP `10.11.90.211`.
    -   **ID de Regla (SID):** Los detalles de la alerta muestran el SID `1000002`.
    -   **Otras Alertas:** También notas "Ping Detected" (tráfico ICMP).

**Preguntas y Respuestas:**
- **¿Cuál es la dirección IP de la máquina que intentó conectarse a la máquina objetivo usando SSH?**
  - `10.11.90.211`
- **¿Qué otro mensaje de regla además del mensaje SSH se detecta en el archivo PCAP?**
  - `Ping Detected`
- **¿Cuál es el sid de la regla que detecta SSH?**
  - `1000002`
