> [!info] Idea principal
> Con Nmap tambien puedo escanear puertos UDP, pero estos escaneos suelen ser mas lentos y menos directos que los escaneos TCP.

## Que es UDP

UDP significa:

```text
User Datagram Protocol
```

Es un protocolo de comunicacion que no establece una conexion previa como TCP.

Esto significa que:

- No hay handshake.
- No siempre hay respuesta del servicio.
- Puede ser mas dificil confirmar si un puerto esta abierto.
- Los escaneos suelen tardar mas.

> [!note] Diferencia rapida
> TCP suele responder de forma mas clara. UDP muchas veces no responde, por eso Nmap puede mostrar estados como `open|filtered`.

## Servicios Comunes en UDP

Algunos servicios tipicos que pueden usar UDP son:

- `53/udp`: DNS.
- `67/udp` y `68/udp`: DHCP.
- `69/udp`: TFTP.
- `123/udp`: NTP.
- `161/udp`: SNMP.
- `500/udp`: ISAKMP/IKE para VPN.

## Comando Basico

Para hacer un escaneo UDP con Nmap:

```bash
nmap -sU --top-ports 200 --min-rate=2000 -Pn 192.168.0.236
```

Este comando escanea los 200 puertos UDP mas comunes de la maquina objetivo.

## Explicacion del Comando

- `nmap`: ejecuta Nmap.
- `-sU`: realiza un escaneo UDP.
- `--top-ports 200`: escanea los 200 puertos mas comunes.
- `--min-rate=2000`: intenta enviar al menos 2000 paquetes por segundo.
- `-Pn`: trata el host como activo aunque no responda a ping.
- `192.168.0.236`: IP de la maquina victima.

> [!tip] eJPT
> Usar `--top-ports 200` ayuda a que el escaneo UDP sea mas rapido, porque escanear todos los puertos UDP puede tardar muchisimo.

## Estados Importantes en UDP

Cuando reviso el resultado, debo fijarme especialmente en la columna `STATE`.

### `open`

El puerto parece estar abierto y hay un servicio respondiendo.

```text
53/udp open domain
```

Este es el resultado mas interesante.

### `open|filtered`

Nmap no puede confirmar si el puerto esta abierto o filtrado.

```text
161/udp open|filtered snmp
```

Esto puede pasar porque:

- El servicio UDP no responde.
- Hay un firewall filtrando paquetes.
- El host descarta paquetes silenciosamente.

### `closed`

El puerto esta cerrado.

```text
999/udp closed unknown
```

### `filtered`

Nmap detecta que algun filtro o firewall esta bloqueando la comunicacion.

```text
500/udp filtered isakmp
```

> [!warning] Importante
> En UDP no basta con ver `open|filtered` y asumir que esta abierto. Hay que confirmarlo con enumeracion adicional.

## Ejemplo de Salida

```text
PORT     STATE         SERVICE
53/udp   open          domain
69/udp   open|filtered tftp
123/udp  open          ntp
161/udp  open|filtered snmp
```

En este ejemplo, los puertos mas interesantes son:

- `53/udp`, porque esta en `open`.
- `123/udp`, porque esta en `open`.
- `161/udp`, porque aunque esta en `open|filtered`, SNMP puede ser interesante y conviene revisarlo.

## Escaneo UDP con Versiones

Para intentar detectar versiones de servicios UDP:

```bash
sudo nmap -sU -sV --top-ports 200 -Pn 192.168.0.236 -oN udp
```

### Que anade `-sV`

`-sV` intenta detectar la version del servicio.

Ejemplo:

```text
53/udp open domain ISC BIND 9.16
```

## Escanear un Puerto UDP Concreto

Si quiero revisar un puerto especifico:

```bash
sudo nmap -sU -p161 192.168.0.236
```

Ejemplo con SNMP:

```bash
sudo nmap -sU -sV -p161 192.168.0.236
```

## Escanear Varios Puertos UDP

```bash
sudo nmap -sU -p53,69,123,161 192.168.0.236
```

Esto es util si quiero centrarme en servicios UDP importantes.

## Flujo Recomendado

> [!example] Metodo practico
> Primero hago un escaneo UDP rapido con `--top-ports`, despues enumero solo los puertos interesantes.

### Paso 1: Escaneo UDP Rapido

```bash
sudo nmap -sU --top-ports 200 --min-rate=2000 -Pn 192.168.0.236 -oN udp_top
```

### Paso 2: Enumerar Puertos Interesantes

Si encuentro `53`, `123` y `161`:

```bash
sudo nmap -sU -sV -p53,123,161 192.168.0.236 -oN udp_servicios
```

### Paso 3: Revisar Scripts de Nmap

Para algunos servicios UDP puedo usar scripts NSE.

Ejemplo con SNMP:

```bash
sudo nmap -sU -p161 --script "snmp*" 192.168.0.236 -oN snmp
```

## Consejos

> [!tip] Consejos utiles
> - UDP puede tardar bastante, asi que conviene usar `--top-ports`.
> - Revisar siempre la columna `STATE`.
> - Priorizar puertos en `open`.
> - Investigar tambien algunos `open|filtered` si el servicio es interesante.
> - Guardar resultados con `-oN` o `-oA`.
