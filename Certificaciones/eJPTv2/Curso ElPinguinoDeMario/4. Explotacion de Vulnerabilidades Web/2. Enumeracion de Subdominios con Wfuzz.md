# Enumeracion de Subdominios con Wfuzz

> [!info] Idea principal
> Un mismo servidor puede alojar ==varias webs distintas en el mismo puerto 80==. Apache decide cual enseñar mirando la cabecera `Host` de la peticion. Eso se llama **virtual hosting**, y significa que entrar por IP me puede dar una pagina vacia mientras que entrar por el nombre correcto me da la web real.

## Que es un Virtual Host

Cuando pido una web, el navegador manda una cabecera con el nombre del sitio:

```text
GET / HTTP/1.1
Host: logan.hmv
```

El servidor mira ese `Host` y decide **que web servir**. Un unico Apache en `192.168.0.224` puede tener configuradas varias:

| Cabecera Host | Web que sirve |
| :--- | :--- |
| `192.168.0.224` | Pagina por defecto (vacia o de Apache) |
| `logan.hmv` | La web principal |
| `admin.logan.hmv` | ==Panel de administracion oculto== |
| `dev.logan.hmv` | Entorno de desarrollo |

> [!tip] Por que me interesa
> Los subdominios suelen esconder ==paneles de admin, entornos de desarrollo o aplicaciones internas== que no estan enlazados desde la web principal. Es de las cosas mas rentables de enumerar.

> [!warning] No confundir con el fuzzing de directorios
> En [[1. Fuzzing Web]] fuzzeo la **ruta** (`/admin`, `/uploads`). Aqui fuzzeo la **cabecera `Host`**. Son dos superficies distintas y hay que hacer las dos.

## Como Detecto que Hay Virtual Hosting

Estas tres pistas me lo chivan:

1. **Nmap me devuelve un nombre de dominio** en `Service Info`, en el `commonName` de un certificado SSL, o en los `smtp-commands`.
2. Entro por IP y la pagina **carga vacia, da error o me redirige** a un nombre que no resuelve.
3. El titulo de la web (`http-title`) esta vacio o dice algo generico.

> [!example] En el escaneo de la maquina logan
> ```text
> 25/tcp open  smtp    Postfix smtpd
> |_smtp-commands: logan.hmv, PIPELINING, SIZE 10240000, VRFY, ...
> | ssl-cert: Subject: commonName=logan
> 80/tcp open  http    Apache httpd 2.4.52 ((Ubuntu))
> |_http-title: Site doesn't have a title (text/html).
> Service Info: Host:  logan.hmv
> ```
> Aparece `logan.hmv` por dos sitios distintos (SMTP y `Service Info`) → ==hay virtual hosting==.

> [!note] Truco del SMTP
> El puerto 25 casi siempre canta el hostname real de la maquina en el banner. Si veo un Postfix abierto, ahi tengo el dominio gratis.

## Configurar /etc/hosts

Ese dominio no existe en internet, asi que mi maquina no sabe resolverlo. Tengo que decirle a mano a que IP corresponde.

```bash
sudo nano /etc/hosts
```

Y anado la linea:

```text
192.168.0.224   logan.hmv
```

O directamente en una linea:

```bash
echo "192.168.0.224 logan.hmv" | sudo tee -a /etc/hosts
```

Compruebo que resuelve:

```bash
ping -c 1 logan.hmv
curl -I http://logan.hmv
```

> [!success] Ahora si
> Con el `/etc/hosts` configurado ya puedo abrir `http://logan.hmv/` en el navegador y ver la web real.

> [!danger] Cada subdominio nuevo hay que anadirlo
> `/etc/hosts` **no acepta comodines**. Si luego descubro `admin.logan.hmv`, tengo que anadirlo tambien:
> ```text
> 192.168.0.224   logan.hmv admin.logan.hmv dev.logan.hmv
> ```

## Enumerar Subdominios con Wfuzz

La idea: mando muchas peticiones a la **misma IP** cambiando solo la cabecera `Host`, y veo cual responde distinto.

### Sintaxis

```bash
wfuzz -c --hc=404,400 --hl=10 -w /usr/share/wordlists/dirbuster/directory-list-lowercase-2.3-medium.txt -H "Host: FUZZ.logan.hmv" -u 192.168.0.224
```

| Parte | Que hace |
| :--- | :--- |
| `-c` | Salida con colores |
| `--hc=404,400` | **Oculta** las respuestas con codigo 404 y 400 |
| `--hl=10` | Oculta las respuestas que tengan 10 lineas |
| `-w` | Diccionario de nombres a probar |
| `-H "Host: FUZZ.logan.hmv"` | ==La clave==: `FUZZ` es donde wfuzz mete cada palabra |
| `-u 192.168.0.224` | La peticion siempre va a la **IP**, no al dominio |

> [!tip] Por que apunto a la IP y no al dominio
> El servidor es el mismo. Lo unico que cambio es la cabecera `Host`, que es lo que hace que Apache me sirva una web u otra. Si apuntara al dominio, el DNS fallaria en cada subdominio inventado.

> [!note] Diccionario en minusculas
> Para subdominios uso `directory-list-lowercase-2.3-medium.txt` porque ==los dominios no distinguen mayusculas==. Ahorro la mitad de peticiones.

### Ejemplo de Salida

```text
********************************************************
* Wfuzz 3.1.0 - The Web Fuzzer                         *
********************************************************

Target: http://192.168.0.224/
Total requests: 207643

=====================================================================
ID           Response   Lines    Word     Chars     Payload
=====================================================================

000000024:   200        1 L      5 W      65 Ch     "12"
000000027:   200        1 L      5 W      65 Ch     "search"
000000022:   200        1 L      5 W      65 Ch     "warez"
...
000000256:   200        1 L      5 W      65 Ch     "admin"
```

> [!bug] Ojo con esta salida
> ==Todos los resultados tienen exactamente el mismo tamano (`65 Ch`)==. Eso es la firma clasica de un **falso positivo**: el servidor devuelve la misma pagina por defecto para cualquier `Host` que no conozca.
>
> La solucion es filtrar tambien por caracteres con `--hh`:
> ```bash
> wfuzz -c --hc=404,400 --hh=65 -w /usr/share/wordlists/dirbuster/directory-list-lowercase-2.3-medium.txt -H "Host: FUZZ.logan.hmv" -u 192.168.0.224
> ```
> Asi solo sobrevive el subdominio que realmente responde algo distinto.

## Filtros de Wfuzz

Sin filtros la salida es inservible. Estos son los que uso:

### Ocultar (hide)

| Filtro | Oculta las respuestas con... |
| :--- | :--- |
| `--hc=404,400` | Esos **codigos** de estado |
| `--hl=10` | Ese numero de **lineas** |
| `--hw=5` | Ese numero de **palabras** |
| `--hh=65` | Ese numero de **caracteres** (el mas fiable) |

### Mostrar solo (show)

| Filtro | Muestra solo las respuestas con... |
| :--- | :--- |
| `--sc=200,301` | Esos **codigos** |
| `--sl=25` | Ese numero de **lineas** |
| `--sw=100` | Ese numero de **palabras** |
| `--sh=1245` | Ese numero de **caracteres** |

> [!example] Como saco el valor a filtrar
> 1. Lanzo wfuzz sin filtros unos segundos y veo que valor se repite en todo (`65 Ch`).
> 2. Corto con `Ctrl+C`.
> 3. Relanzo con `--hh=65`.
>
> Tambien lo puedo sacar a mano antes de empezar:
> ```bash
> curl -s -H "Host: noexisteasdasd.logan.hmv" http://192.168.0.224 | wc -c
> ```

### Otros Parametros Utiles

| Parametro | Que hace |
| :--- | :--- |
| `-t 50` | Numero de hilos (por defecto 10) |
| `-z file,ruta.txt` | Forma alternativa de indicar el diccionario |
| `-f salida.txt` | Guarda el resultado en un archivo |
| `-p 127.0.0.1:8080` | Manda todo por un proxy (Burp Suite) |
| `-b "PHPSESSID=abc"` | Anade una cookie |
| `-X POST` | Cambia el metodo HTTP |
| `--follow` | Sigue las redirecciones |

## Alternativas a Wfuzz

### Gobuster (modo vhost)

```bash
gobuster vhost -u http://logan.hmv -w /usr/share/wordlists/dirbuster/directory-list-lowercase-2.3-medium.txt --append-domain -t 50
```

- `vhost`: modo virtual host (fuzzea la cabecera `Host`).
- `--append-domain`: anade el dominio base a cada palabra (`admin` → `admin.logan.hmv`). ==Sin esto no funciona en Gobuster 3.x==.
- `--exclude-length 65`: descarta respuestas de ese tamano (equivalente al `--hh` de wfuzz).

### Ffuf

```bash
ffuf -u http://192.168.0.224 -H "Host: FUZZ.logan.hmv" -w /usr/share/wordlists/dirbuster/directory-list-lowercase-2.3-medium.txt -fs 65
```

- `-fs 65`: filtra por tamano de respuesta.
- `-fw 5`: filtra por numero de palabras.
- `-mc all`: muestra todos los codigos (util para no perder redirecciones).

### Gobuster DNS (subdominios reales)

Solo sirve si el dominio existe de verdad en internet y tiene registros DNS. En laboratorios normalmente **no** funciona.

```bash
gobuster dns -d dominio.com -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt
```

> [!note] Diferencia entre `dns` y `vhost`
> - `dns` pregunta a un servidor DNS si el subdominio existe → para dominios publicos.
> - `vhost` manda la cabecera `Host` a una IP concreta → ==para laboratorios y maquinas locales==.

## Caso Practico - Maquina logan

### Paso 1: Localizar la Maquina

```bash
sudo arp-scan -I eth0 --localnet
```

```text
Interface: eth0, type: EN10MB, MAC: 00:0c:29:48:bf:ba, IPv4: 192.168.0.8
192.168.0.1     02:10:18:3a:ab:04       (Unknown: locally administered)
192.168.0.224   08:00:27:99:10:63       (Unknown)
...
```

> [!success] Objetivo identificado
> La MAC `08:00:27` es de **Oracle VirtualBox**, asi que la maquina victima es `192.168.0.224`.

### Paso 2: Escaneo con Nmap

```bash
nmap -p- -sS -sC -sV --open --min-rate 5000 -vvv -n -Pn 192.168.0.224 -oN escaneo
```

```text
PORT   STATE SERVICE REASON         VERSION
25/tcp open  smtp    syn-ack ttl 64 Postfix smtpd
|_smtp-commands: logan.hmv, PIPELINING, SIZE 10240000, VRFY, ETRN, STARTTLS, ...
| ssl-cert: Subject: commonName=logan
| Subject Alternative Name: DNS:logan
80/tcp open  http    syn-ack ttl 64 Apache httpd 2.4.52 ((Ubuntu))
|_http-title: Site doesn't have a title (text/html).
|_http-server-header: Apache/2.4.52 (Ubuntu)
MAC Address: 08:00:27:99:10:63 (Oracle VirtualBox virtual NIC)
Service Info: Host:  logan.hmv
```

> [!info] Que saco de aqui
> - Solo dos puertos: **25 (SMTP)** y **80 (HTTP)**.
> - El SMTP y el `Service Info` cantan el dominio ==`logan.hmv`==.
> - La web no tiene titulo → sospecho virtual hosting.

### Paso 3: Confirmar el Virtual Hosting

Entro a `http://192.168.0.224` y **la pagina no carga nada util**. El servidor esta esperando que le pida la web por su nombre.

### Paso 4: Anadir el Dominio a /etc/hosts

```bash
echo "192.168.0.224 logan.hmv" | sudo tee -a /etc/hosts
```

Ahora `http://logan.hmv/` ==si carga la web correctamente==.

### Paso 5: Fuzzear Subdominios

```bash
wfuzz -c --hc=404,400 --hl=10 -w /usr/share/wordlists/dirbuster/directory-list-lowercase-2.3-medium.txt -H "Host: FUZZ.logan.hmv" -u 192.168.0.224
```

Entre los resultados aparece:

```text
000000256:   200        1 L      5 W      65 Ch     "admin"
```

> [!warning] Cuidado con el dominio mal escrito
> Si en el `-H` pongo `logan.mhv` en vez de `logan.hmv`, ==todas las peticiones van a un vhost inexistente== y wfuzz devuelve cientos de respuestas identicas. Merece la pena revisar la cabecera letra por letra antes de lanzarlo.

### Paso 6: Anadir el Subdominio Encontrado

```bash
sudo nano /etc/hosts
```

```text
192.168.0.224   logan.hmv admin.logan.hmv
```

### Paso 7: Acceder al Subdominio

Abro `http://admin.logan.hmv/` en el navegador.

> [!success] Subdominio conseguido
> Ya tengo acceso a una web distinta a la principal. Ahora toca volver a empezar con ella: fuzzing de directorios ([[1. Fuzzing Web]]) y, si hay login, fuerza bruta ([[6. Hydra - Ataques a Panales Web]]).

## Flujo Resumido

> [!example] Pasos tipicos
> 1. `arp-scan` para localizar la maquina en la red.
> 2. `nmap` completo y buscar el **dominio** en `Service Info`, SMTP o certificados SSL.
> 3. Entrar por IP: si la web va vacia o rara → hay virtual hosting.
> 4. Anadir el dominio a `/etc/hosts`.
> 5. Comprobar que la web carga por nombre.
> 6. Sacar el tamano de la respuesta por defecto con `curl ... | wc -c`.
> 7. Lanzar `wfuzz` con `-H "Host: FUZZ.dominio"` y filtrar con `--hh`.
> 8. Anadir cada subdominio encontrado a `/etc/hosts`.
> 9. Volver a empezar: fuzzing de directorios sobre el nuevo subdominio.

## Checklist Rapido

- [ ] Confirmar que tengo permiso para atacar la maquina.
- [ ] Localizar la IP con `arp-scan`.
- [ ] Buscar el dominio en la salida de Nmap (SMTP, SSL, `Service Info`).
- [ ] Anadir el dominio a `/etc/hosts`.
- [ ] Verificar que la web carga por nombre y no por IP.
- [ ] Medir el tamano de la respuesta por defecto para saber que filtrar.
- [ ] Usar un diccionario en **minusculas**.
- [ ] Revisar que la cabecera `Host` esta bien escrita.
- [ ] Lanzar wfuzz con `--hh` (no solo `--hl`).
- [ ] Anadir los subdominios encontrados a `/etc/hosts`.
- [ ] Fuzzear directorios dentro de cada subdominio nuevo.

## Errores Comunes

> [!bug] Salen cientos de resultados, todos iguales
> Es lo mas habitual. El servidor responde lo mismo a cualquier `Host` desconocido.
> - Miro la columna `Chars` y filtro ese valor con `--hh=65`.
> - Si aun asi salen muchos, filtro tambien por `--hw` (palabras).
> - En `ffuf` seria `-fs 65` y en `gobuster` `--exclude-length 65`.

> [!bug] No sale ningun resultado
> - El dominio esta ==mal escrito== en la cabecera `Host` (`logan.mhv` en vez de `logan.hmv`).
> - El filtro es demasiado agresivo y esta ocultando el bueno.
> - El diccionario no tiene el subdominio: probar con otro de SecLists.

> [!failure] El navegador no abre el subdominio
> - Falta anadirlo a `/etc/hosts` (no vale con haber puesto el dominio padre).
> - Cache del navegador o del sistema: limpiar con `sudo systemd-resolve --flush-caches`.
> - Comprobarlo primero con `curl -H "Host: ..."` para descartar que sea cosa del navegador.

> [!warning] Aviso de Pycurl al arrancar wfuzz
> ```text
> UserWarning: Pycurl is not compiled against Openssl.
> ```
> Es solo un aviso. Afecta al fuzzing sobre HTTPS, pero ==en HTTP funciona perfectamente==. Se puede ignorar.
