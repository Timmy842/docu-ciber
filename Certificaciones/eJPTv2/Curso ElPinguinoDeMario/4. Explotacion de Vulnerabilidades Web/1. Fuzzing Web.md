# Fuzzing Web

> [!info] Idea principal
> Cuando en un escaneo veo el **puerto 80** (o 443, 8080...) abierto, la web casi nunca me ensena todo lo que tiene. El fuzzing consiste en probar miles de nombres de un diccionario contra el servidor para descubrir ==rutas, directorios y archivos ocultos== que no estan enlazados en ninguna parte.

## Que es el Fuzzing Web

Un servidor web responde con un codigo distinto segun si el recurso existe o no. El fuzzing aprovecha eso: mando una peticion por cada palabra del diccionario y me quedo con las que **no** devuelven `404`.

```text
GET /admin      →  301   existe
GET /backup     →  200   existe
GET /qwertyasd  →  404   no existe
```

Con esto puedo encontrar:

- Paneles de administracion → `/admin`, `/login`, `/panel`
- Backups o archivos olvidados → `.bak`, `.zip`, `.old`, `.txt`
- Archivos de configuracion o con credenciales
- Rutas de subida de archivos → `/uploads`, `/files`
- Aplicaciones enteras dentro del servidor → `/phpmyadmin`, `/wordpress`

> [!warning] Importante
> El fuzzing genera ==miles de peticiones en pocos segundos== y queda registrado en los logs del servidor. Solo en maquinas propias, laboratorios o entornos con permiso.

## Cuando Hacer Fuzzing

Justo despues del escaneo con Nmap ([[5. Escaneos Basicos con Nmap]]), en cuanto confirmo que hay un servicio HTTP.

```bash
nmap -p- --open -sS -sC -sV --min-rate 2000 -n -vvv -Pn 192.168.1.29 -oN escaneo
```

Si en la salida veo algo asi, ya toca fuzzear:

```text
80/tcp open  http    Apache httpd 2.4.41
```

> [!tip] Antes de lanzar el fuzzer
> Entro primero a la web con el navegador y miro el **codigo fuente** (`Ctrl+U`) y el **`robots.txt`**. Muchas veces ahi ya hay rutas interesantes sin gastar una sola peticion.

## Gobuster

Es la herramienta mas usada para esto: rapida, escrita en Go y con un modo distinto para cada tipo de fuzzing.

### Sintaxis Basica

```bash
gobuster dir -u http://192.168.1.29 -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt
```

| Parte | Que significa |
| :--- | :--- |
| `dir` | Modo de busqueda de **directorios y archivos** |
| `-u` | URL objetivo (siempre con `http://` o `https://`) |
| `-w` | Diccionario (wordlist) a usar |

> [!tip] Wordlist recomendada
> `/usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt` es la mas recomendable para el eJPT: buen equilibrio entre cantidad de rutas y tiempo de ejecucion.

### Ejemplo de Salida

```text
===============================================================
Gobuster v3.6
===============================================================
[+] Url:            http://192.168.1.29
[+] Method:         GET
[+] Threads:        10
[+] Wordlist:       /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt
[+] Status codes:   200,204,301,302,307,401,403
===============================================================
/index.php            (Status: 200) [Size: 1245]
/admin                (Status: 301) [Size: 315] [--> http://192.168.1.29/admin/]
/uploads              (Status: 301) [Size: 317] [--> http://192.168.1.29/uploads/]
/backup.zip           (Status: 200) [Size: 20481]
/phpmyadmin           (Status: 301) [Size: 320]
===============================================================
```

> [!success] Que hago con esto
> Cada linea es una ruta que **existe**. Las voy abriendo en el navegador una a una: `/admin` puede darme un panel de login y `/backup.zip` un archivo descargable con codigo fuente o credenciales.

### Buscar Extensiones con `-x`

Por defecto Gobuster solo prueba nombres "a secas". Con `-x` le digo que ademas pruebe cada palabra con esas extensiones.

```bash
gobuster dir -u http://192.168.1.29 -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt -x php,html,js,txt,sh
```

Asi, por cada palabra del diccionario (por ejemplo `config`) prueba:

```text
/config
/config.php
/config.html
/config.js
/config.txt
/config.sh
```

> [!warning] Multiplica el tiempo
> Con 5 extensiones el escaneo hace ==6 veces mas peticiones==. Si voy justo de tiempo, primero lanzo el fuzzing sin `-x` y luego repito solo con las extensiones que tengan sentido.

> [!tip]- Que extensiones elegir segun la tecnologia
>
> | Tecnologia | Pista | Extensiones |
> | :--- | :--- | :--- |
> | PHP (Apache/Nginx) | `index.php`, `Server: Apache` | `php,txt,html,bak,zip` |
> | ASP.NET (IIS) | `Server: Microsoft-IIS` | `asp,aspx,txt,config` |
> | Java | `.jsp`, Tomcat | `jsp,do,action` |
> | No lo se | — | Miro la cabecera `Server` del escaneo de Nmap |

### Parametros Utiles

| Parametro | Que hace |
| :--- | :--- |
| `-t 50` | Numero de hilos (por defecto 10). Acelera mucho |
| `-x php,txt` | Extensiones a probar |
| `-k` | Ignora errores de certificado SSL (HTTPS invalido) |
| `-b 404,403` | Codigos a **ignorar** (blacklist) |
| `-s 200,301` | Codigos a **mostrar** (whitelist) |
| `-o resultado.txt` | Guarda la salida en un archivo |
| `-e` | Muestra la URL completa en los resultados |
| `-r` | Sigue las redirecciones |
| `-U user -P pass` | Autenticacion basica HTTP |
| `-c "PHPSESSID=abc"` | Manda una cookie (fuzzear zonas privadas ya logueado) |
| `-H "Cabecera: valor"` | Anade una cabecera personalizada |

### Comando Completo Recomendado

```bash
gobuster dir -u http://192.168.1.29 -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt -x php,html,txt -t 50 -o fuzzing.txt
```

### Fuzzing Recursivo (a Mano)

> [!danger] Gobuster NO es recursivo
> No entra solo dentro de los directorios que encuentra. Si descubro `/admin`, tengo que ==volver a lanzarlo apuntando ahi dentro==.

```bash
gobuster dir -u http://192.168.1.29/admin -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt -x php,txt -t 50
```

> [!note] Regla practica
> Cada directorio nuevo que aparece es un objetivo nuevo que hay que volver a fuzzear.

## Dirb (Alternativa)

Si en el examen o en la maquina no esta instalado Gobuster, `dirb` viene por defecto en Kali y hace lo mismo (mas lento, pero funciona).

```bash
dirb http://192.168.1.29 /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt
```

> [!info] Dos diferencias con Gobuster
> 1. La URL y el diccionario van ==posicionales==, sin `-u` ni `-w`.
> 2. `dirb` ==si es recursivo por defecto==: entra solo en los directorios que va encontrando.

### Parametros Utiles

| Parametro | Que hace |
| :--- | :--- |
| `-X .php,.txt` | Extensiones a probar (**con el punto delante**) |
| `-o resultado.txt` | Guarda la salida |
| `-r` | **No** recursivo (solo el primer nivel) |
| `-z 100` | Milisegundos de espera entre peticiones |
| `-c "PHPSESSID=abc"` | Cookie |
| `-a "Mozilla/5.0"` | User-agent personalizado |

```bash
dirb http://192.168.1.29 /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt -X .php,.txt,.html -o fuzzing.txt
```

> [!note]- Diccionario por defecto de dirb
> Si no le paso ningun diccionario usa el suyo propio (`/usr/share/dirb/wordlists/common.txt`), pequeno pero muy rapido para una primera pasada:
>
> ```bash
> dirb http://192.168.1.29
> ```

## Otras Herramientas

| Herramienta | Cuando la uso |
| :--- | :--- |
| **Gobuster** | Mi opcion por defecto |
| **Dirb** | Si no hay Gobuster (viene siempre en Kali) |
| **Ffuf** | La mas rapida y flexible; permite fuzzear parametros |
| **Wfuzz** | La clasica, alternativa a ffuf |
| **Dirsearch** | Trae diccionario y extensiones ya configuradas |
| **Nmap** | Ultimo recurso si no hay nada instalado |

### Ffuf

Usa la palabra clave `FUZZ` para marcar ==donde== va cada palabra del diccionario.

```bash
ffuf -u http://192.168.1.29/FUZZ -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt
```

Con extensiones y filtrando el codigo 404:

```bash
ffuf -u http://192.168.1.29/FUZZ -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt -e .php,.txt,.html -fc 404 -t 100
```

| Parametro | Que hace |
| :--- | :--- |
| `-e .php,.txt` | Extensiones |
| `-fc 404` | **Filtra** (oculta) las respuestas con ese codigo |
| `-fs 1234` | Filtra por tamano de respuesta |
| `-mc 200,301` | **Muestra** solo esos codigos |
| `-t 100` | Hilos |

> [!tip] La ventaja de ffuf
> Como `FUZZ` puede ir en cualquier sitio, tambien sirve para fuzzear **parametros**:
>
> ```bash
> ffuf -u "http://192.168.1.29/index.php?FUZZ=1" -w /usr/share/wordlists/dirb/common.txt -fs 1245
> ```

### Wfuzz

```bash
wfuzz -c --hc=404 -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt http://192.168.1.29/FUZZ
```

### Dirsearch

```bash
dirsearch -u http://192.168.1.29 -e php,html,txt
```

### Nmap

```bash
nmap -p80 --script http-enum 192.168.1.29
```

> [!note] Ultimo recurso
> Es mucho menos completo que Gobuster, pero si estoy en una maquina sin herramientas sirve para salir del paso.

## Fuzzing de Subdominios y Virtual Hosts

Si la maquina responde por un **dominio** y no solo por IP, puede haber webs distintas escondidas detras del mismo puerto 80.

### Subdominios (DNS)

```bash
gobuster dns -d dominio.com -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt
```

### Virtual Hosts (cabecera Host)

```bash
gobuster vhost -u http://dominio.com -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt --append-domain
```

> [!warning] Antes hay que resolver el dominio
> Si el dominio no existe en internet (tipico en laboratorios), lo anado a mano en `/etc/hosts`:
>
> ```bash
> echo "192.168.1.29 dominio.com" | sudo tee -a /etc/hosts
> ```

## Codigos de Respuesta que me Interesan

| Codigo | Significado | Que hago |
| :--- | :--- | :--- |
| `200` | Existe y me lo devuelve | ==Lo mejor==, lo abro en el navegador |
| `301` / `302` | Redireccion | Casi siempre el directorio existe |
| `401` | Pide autenticacion | Candidato a fuerza bruta con Hydra |
| `403` | Existe pero no me deja verlo | **Info valiosa**: confirma la ruta |
| `404` | No existe | Lo filtro |
| `500` | Error del servidor | Algo esta roto → puede ser explotable |

> [!tip] No ignorar los 403
> Un `403` en `/admin` me confirma que ese panel ==existe==. Puedo intentar entrar por otra ruta (`/admin/index.php`, `/admin/login.php`) o buscar bypasses.

## Flujo Resumido

> [!example] Pasos tipicos
> 1. Escanear con Nmap y confirmar el puerto 80 / 443 / 8080 abierto.
> 2. Abrir la web en el navegador, mirar el codigo fuente y el `robots.txt`.
> 3. Identificar la tecnologia (PHP, ASP, Java) para elegir extensiones.
> 4. Lanzar Gobuster con `directory-list-2.3-medium.txt`.
> 5. Repetir con `-x` y las extensiones que tocan.
> 6. Revisar cada resultado `200`, `301`, `401` y `403` en el navegador.
> 7. Volver a fuzzear **dentro** de cada directorio encontrado.
> 8. Si aparece un panel de login → fuerza bruta con Hydra.

## Checklist Rapido

- [ ] Confirmar que tengo permiso para atacar la maquina.
- [ ] Verificar con Nmap que el servicio HTTP esta abierto y en que puerto.
- [ ] Revisar `robots.txt` y el codigo fuente antes de fuzzear.
- [ ] Elegir el diccionario (`directory-list-2.3-medium.txt`).
- [ ] Lanzar Gobuster sin extensiones (pasada rapida).
- [ ] Repetir con `-x` segun la tecnologia detectada.
- [ ] Guardar la salida con `-o`.
- [ ] Anotar todos los `200`, `301`, `401` y `403`.
- [ ] Fuzzear recursivamente cada directorio encontrado.
- [ ] Probar tambien HTTPS y puertos alternativos (8080, 8443).

## Errores Comunes

> [!bug] Si Gobuster no devuelve nada o devuelve todo
> - **Error "the server returns a status code that matches the provided options"**: la web devuelve `200` en cualquier ruta. Se soluciona filtrando por tamano de respuesta (`--exclude-length`) o usando `ffuf` con `-fs`.
> - **Todo sale como valido**: pagina de error personalizada que responde `200` en vez de `404`. Comprobar a mano con una ruta inventada.
> - **No encuentra nada**: la URL esta mal (falta `http://`), es el puerto equivocado, o la app esta bajo un subdirectorio (`/app/`, `/web/`).
> - **Error de certificado en HTTPS**: falta el flag `-k`.
> - **Va lentisimo**: subir `-t` (por ejemplo `-t 50`) o usar un diccionario mas pequeno.
> - **Se me olvida ser recursivo**: Gobuster **no** entra en los subdirectorios por si solo.

> [!failure] Falsos negativos
> Un WAF o un rate limit puede empezar a devolver `429` o cortar las conexiones si voy demasiado rapido. Si a mitad de escaneo dejan de aparecer resultados, bajo los hilos (`-t 10`) y vuelvo a probar.
